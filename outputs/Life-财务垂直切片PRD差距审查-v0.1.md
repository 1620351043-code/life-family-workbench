判定规则：

- 数据库有表，不等于功能已完成；必须同时有 API、权限、前端交互、状态反馈和测试。
- OpenAPI 有声明，不等于运行时有路由；以 `server.ts` 实际注册路由为准。
- 能从首页下钻查看，不等于具备记账、编辑、撤销、审计等写入能力。
- 演示/种子数据能展示，不等于用户能在移动端完成真实操作。

## 2. 总体结论

当前财务交付应重新定义为：

```text
已完成：财务首页读模型 + 服务端下钻 + 统一账单详情
已完成：文件导入、非首行表头预览、来源关联审核、银行锚定去重提交
缺失：可写的家庭账本基础能力（账户、分类、手动记账、转账、分录）
缺失：预算/资产/权限/审计管理页面和运行时 API
部分完成：多来源关系已保存，但父子结算、退款、手续费、拆分等专项入账规则尚未实现
```

因此，当前不能把财务描述为“PRD 所要求的完整首发财务功能已完成”。目前更准确的名称是“财务可视化与账单导入基础闭环”。

## 4. 关键差距详审

### 4.1 新增记账完全缺失，是当前最大断点

PRD 5.3.1、5.3.2、7.4、9.1 和页面清单明确要求用户可以手动记账。当前实现证据如下：

- `FinanceRepository` 只有概览、下钻、交易详情和导入状态机方法，没有创建/修改/撤销账本交易的方法。
- `src/api/server.ts` 没有 `POST /api/finance/transactions`、编辑或撤销账单路由。
- `FinancePage.tsx` 只有“导入账单”和刷新入口，没有“新增记账”入口。
- 空态文案写着“完成账单导入或新增一笔记录后”，但用户实际上无法新增记录。
- 数据库没有 `manual` 来源或手动记账事件模型，`ledger_transaction` 的 `import_batch_id` 也允许为空，但没有对应写入流程。

建议补齐的最小闭环：

1. 选择账户、收支方向、金额、日期时间、分类、商户/对象、备注。
2. 支持收入、支出和转账；转账必须选择转出账户和转入账户。
3. 保存后立即更新账户余额、账本、预算和趋势。
4. 支持进入详情修改、撤销；修改前后写入审计。
5. 手动记录必须与导入记录使用同一 `LedgerTransaction` 统计口径。

### 4.2 账本模型存在，但正式入账不完整

PRD 定义的是 `LedgerTransaction` + `LedgerEntry`，并明确要求收入、支出、转账分离。当前迁移虽然建立了两张表，但导入提交只执行 `INSERT INTO ledger_transaction`，没有为交易写入 `ledger_entry`。

这会导致：

- `getTransactionDetail` 能查询分录，但正式导入交易的分录可能为空。
- 账户余额无法由账户分录可靠计算。
- 转账无法表达“账户 A 减少、账户 B 增加”这两个方向。
- 净资产和账户余额没有可信的计算基础。

这不是单纯的页面缺失，而是财务核心数据正确性问题。下一轮必须先确定分录方向、金额正负、账户余额计算和转账约束，再开放手动记账。

### 4.3 分类和预算目前是“可读数据”，不是“可管理功能”

当前首页能读取 `budget_period`、`budget`、`category` 并绘制多环，但没有：

- 创建、编辑、归档分类；
- 分类的收入/支出适用范围；
- 预算金额、周期、分类和生效日期编辑；
- 当前周期预算与未来周期预算的版本化；
- 超预算状态、预算调整历史和审计；
- 从记账表单选择分类并校验方向。

此外，`ledger_transaction.category` 当前是文本字段，预算查询通过分类名称匹配交易文本，存在改名、同名和拼写差异导致统计断开的风险。应改为稳定的 `category_id` 或等价的家庭范围引用，并保留显示名称快照。

### 4.4 账户与净资产缺失

PRD 首页要求净资产、账户余额和账户/资产页面。当前 `financial_account` 只有名称、类型、币种和 opening balance；没有：

- 账户列表、账户详情和余额快照；
- 账户余额由分录计算的服务；
- 现金、银行卡、支付宝、微信钱包之间的账户关系；
- 账户归档、期初余额修正和审计；
- 净资产计算及下钻。

因此当前财务首页的三张卡不能代表完整财务状态，缺少账户层和资产负债口径。

### 4.5 实物资产只有趋势读模型

当前页面可以读取 `asset_event` 生成趋势，但 PRD 要求资产登记、资产事件和成本趋势。现在没有：

- 新增/编辑实物资产；
- 资产详情、当前持有状态和生命周期；
- 购买、维修、耗材、升级、转让、出售、处置事件录入；
- 资产事件与账单的双向关联；
- 单个资产成本曲线和事件下钻。

测试和移动端种子脚本直接插入 `physical_asset`、`asset_event`，说明当前展示依赖测试准备数据，而不是用户可操作的资产功能。

### 4.6 多来源关系的“保存”与“入账”尚未完全一致

当前关联审核能保存多种 `transaction_link` 类型，但导入提交时只将 `duplicate` 关系做并查集去重。`parent_settlement`、`refund_reversal`、`fee_related`、`split` 等已确认关系没有对应的正式账本处理规则。

如果这些关系确认后仍分别生成普通支出交易，就可能出现：

- 父子结算重复统计；
- 退款没有冲减原支出；
- 手续费未单独入账或被吞掉；
- 拆分交易无法进入多个分类。

导入切片当前应从“去重提交完成”降级为“重复关系提交完成，专项关系待补齐”。

### 4.7 财务权限与家庭所有者授权未落地

当前 RLS 解决的是家庭之间隔离，不等于家庭成员之间的财务权限。PRD 要求所有者可以逐项管理儿童和成员的财务查看、记账、编辑、导入、关联、导出权限。

当前没有：

- `FinancialPermission` 数据表或等价策略；
- 权限范围、授权人、授权时间、撤销时间；
- 服务端写操作权限检查；
- 儿童默认无财务权限的运行时验证；
- 财务页面的无权限、授权申请或权限变化状态。

这必须在任何财务写入功能正式上线前完成，否则“家庭隔离”会被误认为“成员权限已完成”。

### 4.8 财务审计、撤销和保留期只有字段或局部状态

- `audit_log` 表存在，但当前财务仓储没有对手动记账、预算修改、资产修改、关联确认等操作统一写审计。
- 导入撤销会把批次生成的交易设为 `voided`，但没有形成完整的财务操作审计证据。
- `raw_retention_until` 已写入批次，但没有看到清理 worker、对象删除、数据库中间数据清理和清理审计的生产闭环。

因此“有表/有字段”不能判定为审计和一年保留已完成。

### 4.9 财务首页与 PRD 页面清单不一致

PRD 页面清单要求：

- 财务首页；
- 账户与资产；
- 账户详情；
- 收支明细；
- 全部流水；
- 新增记账；
- 预算与分类；
- 导入账单；
- 导入关联审核；
- 实物资产详情和成本趋势；
- 财务设置和审计。

当前前端实际只有一个 `FinancePage`，其中包含首页卡片、下钻 Sheet、交易详情 Sheet 和导入向导。账户、记账、预算管理、资产管理、财务设置和审计均没有独立页面或路由。

## 5. 当前已完成范围应如何重新标记

### 可以保留为已完成

- 财务首页真实 PostgreSQL 读模型的第一版。
- 摘要卡、预算多环、收支趋势、实物资产成本趋势的基础展示和下钻契约。
- 统一账单详情对银行锚点、平台来源和关联关系的读取。
- 银行、支付宝、微信、记账 App 真实样本的 CSV/XLS/XLSX 解析回放。
- 非首行表头预览、字段映射、重复候选、用户确认和银行锚定去重提交。
- 同一导入批次重复提交幂等、版本冲突和撤销的基础状态机。

### 必须从“完成”改成“部分完成/待补齐”

- 完整家庭财务 V1：当前只是可视化与导入基础闭环。
- 统一账本：当前只创建交易主记录，分录和账户余额链路未闭合。
- 多来源关联：重复关系可提交，父子结算、退款、手续费、拆分尚未入账。
- 实物资产：趋势查询完成，资产管理和事件写入缺失。
- 财务权限与审计：家庭 RLS 有，成员级财务授权和业务审计缺失。

## 6. 建议的补齐顺序

### P0-A：账本基础与新增记账

- 先确定 `LedgerEntry` 分录语义和账户余额计算规则。
- 补账户列表/详情、分类选择、手动支出、手动收入、转账。
- 让导入交易与手动交易都写入完整分录。
- 补编辑、撤销、幂等、审计和家庭/成员权限检查。

### P0-B：预算与分类管理

- 分类 CRUD、方向约束、颜色和归档。
- 预算创建、当前/未来周期编辑、预算规则版本和历史不变性。
- 预算环与预算明细使用 `category_id` 关联。
- 超预算、无预算、预算调整和审计状态完整落地。

### P0-C：账户与资产管理

- 账户余额、期初余额、归档和净资产。
- 资产登记、详情、事件录入和事件与账单关联。
- 单资产成本趋势、生命周期和出售/转让/处置。

### P0-D：成员财务权限与审计

- 所有者管理查看、记账、编辑、导入、关联、导出权限。
- 儿童默认无权限，逐项授权且可撤销。
- 所有财务写入、权限变更、AI 建议和导出统一写审计。

### P1-A：导入专项关系与格式能力

- 父子结算、退款/冲正、手续费、拆分的入账规则和账单展示。
- PDF/ZIP、多数据区域、多行表头、合并单元格和 OCR 低置信度处理。
- 解析队列、重试、超时、进度、死信和 COS 生命周期。

### P1-B：财务 AI

- 对账、预算超支、趋势异常和本月摘要。
- 财务 AI 来源引用、权限校验、提案确认/拒绝/撤销和审计。
