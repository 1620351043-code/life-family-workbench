## 1. 结论

`B-010` 在当前仓库范围达到 `DONE`：移动端已提供家庭隔离、AI 隔离、原始账单 365 天保留、数据导出边界、账号删除和家庭删除的统一说明；删除操作使用服务端等待期、输入确认短语、可撤销计划、版本冲突和审计闭环。

本切片只创建删除计划，不在 HTTP 请求内物理删除数据。真正的级联删除执行器必须在目标 PostgreSQL、对象存储、家庭 AI 记忆、搜索索引、任务和备份环境中独立验收，不得把“计划已创建”标记为“数据已删除”。

| 能力 | 首发规则 | 权限 | 当前状态 |
|---|---|---|---|

| 删除成员账号 | 7 天等待期；停用登录、移除成员关系、清理个人 AI 记忆；家庭内容匿名保留 | 非所有者只能申请自己的账号 | 计划创建/撤销可用；执行器未包含 |
| 删除整个家庭 | 14 天等待期；家庭业务数据、原始文件、AI 记忆/索引和会话进入异步级联清理 | 仅家庭所有者 | 计划创建/撤销可用；执行器未包含 |

家庭所有者不能单独删除账号，避免形成无所有者家庭；需要先完成必要导出，再申请删除整个家庭。等待期以服务端时间计算，状态进入 `processing` 后页面不再提供撤销。

## 3. 数据与 API

- 迁移：`db/migrations/0014_data_rights_deletion_requests.sql`。
- `data_deletion_request` 按家庭隔离，保存类型、状态、版本、申请人、执行时间、影响摘要和结束结果。
- 同一家庭/账号只允许一个同类型的活跃计划；使用部分唯一索引阻止并发重复申请。
- 表启用并强制 RLS；`life_app` 只能读取，创建和撤销必须通过 `SECURITY DEFINER` 函数。
- `GET /api/data-rights`：返回服务端生效的数据政策、导出能力、删除等待期和当前可见计划。
- `POST /api/data-rights/deletion-requests`：创建账号或家庭删除计划。
- `POST /api/data-rights/deletion-requests/{requestId}/cancel`：携带 `expected_version` 撤销尚未进入处理的计划。
- 家庭删除计划对当前家庭成员可见；账号删除计划只向申请人可见。其它家庭不能通过 ID 或列表读取。
- 审计动作覆盖账号/家庭计划创建和计划撤销，影响摘要不写入原始敏感内容。

- 入口：`更多 → 数据与安全`。

- 成功后使用 API 响应原位更新计划卡，不轮询、不整页刷新；撤销同样原位更新。
