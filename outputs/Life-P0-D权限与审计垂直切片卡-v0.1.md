## 1. 切片目标

把“家庭租户隔离”扩展为“家庭成员级财务授权”，并让授权变化、财务写入和 AI 财务动作都能追溯：

```text
家庭所有者 → 按成员授予能力 → 服务端每次请求校验 → 财务操作写入审计
           → 可撤销 → 撤销后立即拒绝对应能力
```

## 2. 权限模型

财务能力按最小权限拆分：

| 能力 | 作用 | 默认值 |
|---|---|---|
| `can_view` | 查看账户、分类、预算、资产、流水、下钻和 AI 来源 | 所有者/成年成员按角色；儿童关闭 |
| `can_bookkeep` | 新增手动记账 | 关闭 |
| `can_edit` | 编辑/归档账户、分类、预算、资产 | 关闭 |
| `can_import` | 上传、解析、表头确认、字段映射 | 关闭 |
| `can_reconcile` | 关联审核、提交、撤销导入和 AI 提案确认 | 关闭 |
| `can_export` | 导出财务数据的授权位 | 关闭，导出执行能力后续接入 |

- 家庭所有者拥有管理成员财务权限和查看财务审计的能力。
- 儿童成员没有默认财务访问权；所有能力必须由所有者逐项授予。
- 普通成员不能管理权限，也不能读取其它家庭的数据。
- 撤销以显式全 false 记录保存，不删除历史授权和审计。
- 服务端检查与前端 disabled 状态同时存在；前端不能作为安全边界。

## 3. API 契约

| 方法 | 路径 | 目的 |
|---|---|---|
| `GET` | `/api/finance/permissions` | 所有者查看成员授权和当前家庭审计摘要 |
| `PATCH` | `/api/finance/permissions/{userId}` | 所有者逐项授予/修改能力 |
| `POST` | `/api/finance/permissions/{userId}/revoke` | 撤销成员全部财务能力 |
| `GET` | `/api/finance/audit` | 所有者读取财务审计记录 |

所有财务读写 API 在仓储层执行家庭和能力检查：`view`、`bookkeep`、`edit`、`import`、`reconcile`。审计记录包含 action、资源、操作前后摘要、操作者和 trace id。

## 4. 数据与安全

- 新增 `financial_permission`，使用家庭与成员唯一约束，保存显式授权、角色默认值、授权时间和撤销时间。
- 权限表和审计查询均受家庭 RLS 保护，并通过应用角色访问。
- 权限变更、账户/分类/预算/资产/资产事件/手动记账/编辑/撤销/导入关联/AI 提案均使用统一财务审计写入器。
- 取消、撤销和拒绝不物理删除来源账单或历史审计。

## 5. 移动端 UI/UX 验收标准

- “账户与预算”管理 Sheet 增加“权限”页，不增加新的一级导航，避免财务首页入口膨胀。
- 权限页先显示当前操作者和“仅家庭所有者可修改”的状态说明，再按成员卡片展示能力开关。
- 每个开关同时展示能力名称和结果；保存后给出即时状态，撤销使用明确的危险色和可回溯提示。
- 审计列表只展示必要摘要，长内容可换行或在 Sheet 内滚动，不将敏感原始账单直接铺开。
- 所有开关、保存、撤销、关闭入口不小于 44×44pt；430×932 与 320×900 下无横向溢出。
- 儿童无权访问时，使用“暂未获得家庭财务权限”的可解释空态，不暴露金额或来源记录。
