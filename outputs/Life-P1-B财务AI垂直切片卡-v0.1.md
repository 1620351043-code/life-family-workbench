## 1. 切片目标

在不自动改账的前提下，让用户从财务上下文获得可解释、可回溯、可撤销的周期摘要：

```text
财务周期 → 读取统一账本/预算/资产 → 生成解释与来源引用
         → 待确认提案 → 确认/拒绝/撤销 → 审计
```

## 2. 当前实现

- 新增 `0008_finance_ai.sql`，允许财务范围 AI 洞察和 `finance_review` 提案。
- `GET /api/finance/ai/summary` 生成当前家庭和周期范围的确定性财务摘要。
- 摘要覆盖收入、支出、净现金流、最高支出分类、预算临界度、实物资产净现金成本和来源解释。
- 每条摘要包含 `source_refs`，可以指向周期总账、统一账单、原始来源、预算规则或资产事件。
- `finance_review` 提案支持 `proposed → confirmed/rejected`，并支持 `proposed/confirmed → revoked`。
- 确认只写入 AI 行动执行记录，`formal_ledger_mutation=false`，不会自动合并账单、改账或改变预算。
- 生成、确认、拒绝和撤销均进入财务审计。

## 3. 权限与隔离

- 生成摘要需要 `can_view`；确认、拒绝和撤销需要 `can_reconcile`。
- 查询、来源引用、洞察、提案和执行记录都绑定当前家庭。
- 当前 Provider 是 `deterministic-finance-v1`，仅用于可重复开发验收；没有把它包装成真实大模型。
- 生产 Provider、家庭独立 API 凭据、家庭独立 AI 记忆文件和删除/保留策略仍按 PRD 8.6 与 12.1.1 进入发布前硬化。

## 4. 移动端 UI/UX 验收标准

- 财务首页在资产成本趋势之后提供“小兔子 · 财务解读”上下文入口，不抢占“新增记账”主动作。
- Bottom Sheet 首屏明确当前周期、只读边界和数据来源；加载、错误、空数据和已确认状态均可解释。
- 发现、解释、来源和提案按渐进披露分区；来源按钮进入真实财务下钻，而不是复制一份静态摘要。
- 提案必须明确“不会自动改账”，提供“暂不采纳”“确认已了解”和撤销入口。
- 430×932 / 320×900 下 Sheet 内部滚动、无横向溢出，按钮和来源行满足 44pt 触控目标。
