# Life B-004/B-005 移动端身份入口垂直切片卡 v0.1

更新时间：2026-08-27

## 1. 本切片目标

在不伪造身份状态的前提下，为移动端建立正式登录、注册并创建唯一家庭、会话恢复和退出入口。页面复用 Life 淡粉淡紫设计系统，身份成功后才允许进入家庭空间、吃什么、财务和更多。

本切片关闭：

- `B-004` 移动端登录页。
- `B-005` 移动端注册/创建家庭。

本切片不关闭：

- `B-006` 密码重置。当前只提供诚实边界说明，不发送虚假邮件。
- `B-007` 邀请码加入家庭。
- `B-008` 家庭成员和角色管理。
- `B-011` 目标 PostgreSQL + HTTPS 环境的正式身份 E2E。
- `G-004` 全局敏感接口和多实例共享限流。
- `G-005` 泄漏口令库检查和完整密码策略。

## 2. 用户流程与页面状态

| 流程 | 页面状态 | 反馈与恢复 |
|---|---|---|
| 首次打开 | 会话检查 | 小兔子加载状态；`/api/me` 成功进入工作台，401 进入登录 |
| 登录 | 默认表单 | 邮箱、密码、显示/隐藏密码、忘记密码入口和主按钮 |
| 输入错误 | 表单内错误 | 不跳页；错误区即时显示，用户可原位修正 |
| 凭据错误 | 服务端 401 | 统一提示“邮箱或密码不正确”，不暴露邮箱是否存在 |
| 尝试过多 | 服务端 429 | 展示 `Retry-After` 换算后的剩余等待时间 |
| 登录成功 | 身份态 | HttpOnly Cookie 建立；进入当前账号唯一家庭 |
| 刷新页面 | 会话恢复 | 通过 `/api/me` 恢复家庭、角色和用户信息 |
| 创建家庭 | 注册表单 | 家庭名称、邮箱、密码和“唯一家庭”明确确认 |
| 弱密码 | 客户端 + 服务端 400 | 至少 8 位；保留在当前表单修正 |
| 邮箱已注册 | 服务端 409 | 明确不能创建第二个家庭，不自动转入其他家庭 |
| 注册成功 | owner 身份态 | 一次性创建用户、家庭、owner 成员和会话 |
| 退出登录 | 更多页 | 撤销当前会话并返回登录页，不做危险的静默重试 |
| 忘记密码 | 功能边界页 | 明确 B-006 尚未开放，不伪造邮件发送成功 |

## 3. UI/UX 契约

- 页面内容使用近白实体卡片，淡粉与淡紫只承担环境氛围；身份卡片和输入区不使用重玻璃造成可读性损失。
- 登录页单屏只保留一个主要动作；登录/创建家庭使用可预测的分段控件切换。
- 所有可见按钮、输入框和复选框命中区不小于 44pt。
- 输入框使用 iOS 合理键盘提示、`autocomplete`、邮箱小写和密码显示切换。
- 主按钮在提交期间锁定并显示即时加载反馈，避免重复提交。
- 错误留在当前上下文，不用 Toast 覆盖重要表单；服务状态提供明确重试入口。
- 320、390、430 三档宽度不得横向溢出；动态邮箱和家庭名由容器约束处理。
- 尊重 `prefers-reduced-motion`，关闭非必要加载动画。

## 4. API 与安全契约

| API | 成功 | 主要失败 |
|---|---|---|
| `POST /api/auth/login` | 返回身份并设置 HttpOnly Cookie | 400、401、429、503 |
| `POST /api/auth/register` | 201，创建唯一家庭并设置 Cookie | 400、409、429、503 |
| `GET /api/me` | 返回当前用户、家庭和角色 | 401、503 |
| `POST /api/auth/logout` | 204 并清除 Cookie | 401、503 |

当前安全实现：

- 注册密码后端强制 8–128 位，登录兼容既有密码长度。
- 登录失败不区分“账号不存在”和“密码错误”。
- 登录与注册按操作、邮箱和 IP 的哈希键进行失败计数；原始邮箱不写入限流内存键。
- 达到阈值后返回 429、`Retry-After` 和 `retry_after_seconds`。
- 成功登录或注册后清除对应失败计数。

当前边界：限流器为单进程内存实现，只能作为本地和单实例基础保护。生产多实例必须改为共享限流存储，并继续覆盖邀请码、上传、评论、导入和 AI 等敏感接口。
