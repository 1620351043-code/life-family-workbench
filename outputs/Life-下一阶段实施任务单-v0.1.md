## P0：财务真实闭环（基础导入、P0-A、P0-B、P0-C、P0-D 已完成）

### 1. 账本锚定和去重复提交

- 规则：银行记录作为正式账本锚点；支付宝/微信/记账 App 作为详情来源或待关联记录。
- 已确认重复：不重复产生统一账本交易，但保留所有来源记录和关系。
- 未确认关联：不得自动进入正式账本；必须进入关联审核。
- 提交、重复提交、撤销必须使用幂等键和版本校验。
- 当前已落地：确认重复组件只生成一笔交易，优先银行锚点；已有锚点复用，平台来源通过详情回溯。

### 2. 真实账单补测

- 用脱敏银行、支付宝、微信和记账 App 文件补测非首行表头、编码、金额、方向、商户和备注字段。
- 固化每个来源的解析器 fixture、字段映射和异常样本。
- 验收：同一消费跨银行/支付平台导入后，统一账本只计一次，详情页能回溯全部来源。
- 当前样本已完成真实解析回放，结果已写入 `import_row/source_record`；跨来源候选进入 `pending_review`，用户确认后才提交统一账本。
- 表头确认页读取批次级 `header_preview`，展示行号和单元格内容；点击任意行会同步调整表头行与数据起始行，避免用户离开 Life 另行打开表格。

### 3. 财务运行时 API

- 补齐 `/api/me` 和 `/api/finance/transactions/{transactionId}` 运行时实现。
- 摘要卡、预算多环、收入/支出趋势、实物资产成本趋势的每个点都返回可执行 `drilldown_ref`。
- 移动端优先接入真实 PostgreSQL，不再使用财务 fixture 作为默认成功路径。

### 4. 本轮剩余硬化

- 解析 API 当前同步拉起隔离 worker；生产部署再接入队列、重试、超时、进度和死信监控。
- `header_preview` 与批次原始对象遵循同一年的保留策略，清理任务需要在生产部署演练中验证。
- 腾讯云 COS 适配不阻塞本地垂直切片，但在生产发布闸门前必须补齐私有桶、签名访问和生命周期清理。
