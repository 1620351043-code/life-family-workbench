## 0. 文档使用规则

### 0.1 唯一用途

本报告用于回答并持续更新以下问题：

1. 当前产品已经真实完成了什么。
2. 距离单家庭受控内测、完整 V1.0 和多个独立家庭租户正式运营分别还缺什么。
3. 下一项应推进哪个工作包。
4. 每项工作怎样才算完成，需要留下什么证据。
5. 后续更换模型、开发者或执行环境时，如何继续推进而不重复劳动或误报进度。

### 0.2 状态定义

所有清单项只能使用以下状态：

| 状态 | 含义 | 允许使用的证据 |
|---|---|---|
| `DONE` | 已实现并达到本项全部验收标准 | 当前源码、自动化测试、移动端实测、目标环境记录 |
| `PARTIAL` | 已有部分实现，但至少一项验收标准未满足 | 明确列出已完成和未完成部分 |
| `BLOCKED` | 需要外部凭据、服务器权限或单向门决策，当前无法继续 | 阻塞原因、责任人或解除条件 |
| `NOT_STARTED` | 尚无可验证实现 | 不得用设计稿或计划文档代替实现 |
| `N/A` | 经产品决策明确不做 | 必须记录决策日期和依据 |

### 0.3 完成判定纪律

以下情况**不能**标记为 `DONE`：

- 只有 PRD、设计稿、接口草案或“已完成”说明。
- 页面能打开，但使用的是 fixture、前端内存数据或静态样本。
- 后端接口存在，但移动端没有入口或无法完成任务。
- 自动化测试通过，但没有覆盖正式身份态、权限态或真实数据。
- PGlite 通过，但目标原生 PostgreSQL 尚未验证。
- COS 适配器已实现，但没有在真实私有桶完成上传、读取、签名和删除。
- AI 返回了内容，但没有家庭独立连接、来源、权限、确认和审计。
- 仅在 430px 截图正常，没有完成 390px、320px、真机或系统返回手势验证。

### 0.4 后续模型交接协议

后续模型或开发者开始工作前必须：

1. 阅读本文件。
2. 阅读 `outputs/Life-家庭生活工作台-PRD-v0.10.md`。
3. 阅读 `PROJECT_BASELINE.md` 和相关垂直切片卡。
4. 执行本文件第 4 节的基线检查，确认报告是否已经漂移。
5. 从第 8 节中选择**最前面的未关闭阻塞项**推进。
6. 完成后更新本文件中的状态、证据、复核日期和变更日志。
7. 不删除历史结论；发生变化时新增记录并说明替代关系。

## 4. 每轮开始前的基线检查

后续每轮推进前先运行：

```bash
git status --short
npm run web:typecheck
npm run api:typecheck
npm run web:build
npm run api:test
npm run openapi:validate
node db/migration_smoke_test.mjs
npm audit --audit-level=high --registry=https://registry.npmjs.org
```

涉及吃什么时追加：

```bash
npm run web:food-smoke
```

涉及真实账单导入时追加：

```bash
npx tsx scripts/finance_real_bill_vertical.ts
```

涉及腾讯云生产环境时，只有在环境变量、权限和备份确认完成后才能执行：

```bash
npm run production:preflight
```

生产 preflight 会访问真实 PostgreSQL 和 COS，不得在缺少授权或使用不确定凭据时执行。

## 5. 全局 Definition of Done

任何 P0 页面或业务切片必须同时满足以下条件：

- [ ] `DOD-01` 产品范围、用户角色、权限和失败边界明确。
- [ ] `DOD-02` 页面入口、返回路径、系统返回手势和深层页面关系完整。
- [ ] `DOD-03` 使用真实 API 和数据库，不依赖前端 fixture 或刷新即丢失的内存状态。
- [ ] `DOD-04` 所有读写均绑定服务端会话和家庭租户。
- [ ] `DOD-05` 儿童、成人、所有者、无权限和权限变化状态验证通过。
- [ ] `DOD-06` 首次使用、加载、空数据、处理中、成功、失败、重试、离线、资源删除和撤销状态齐全。
- [ ] `DOD-07` 写操作具备幂等、重复提交保护或明确冲突处理。
- [ ] `DOD-08` 关键操作写入审计日志。
- [ ] `DOD-09` API、OpenAPI、迁移和前端调用契约一致。
- [ ] `DOD-10` 自动化测试覆盖正常路径、越权路径和至少一个失败路径。
- [ ] `DOD-11` 430px、390px、320px 无横向溢出，关键控件触控区不低于 44pt。
- [ ] `DOD-12` 真机或真实移动浏览器完成端到端任务。
- [ ] `DOD-13` VoiceOver/键盘焦点、动态文字、对比度和错误播报完成基本验收。
- [ ] `DOD-14` 数据来源、AI 推断和用户确认事实能够区分并下钻。
- [ ] `DOD-15` 对应文档、清单状态和验收证据已更新。

## 13. 审计证据限制

本轮结论存在以下明确边界：

- API 测试主要运行于 PGlite，不是目标服务器的原生 PostgreSQL。
- 当前移动端验收服务已使用 `SqlAuthStore`、scrypt 密码和 HttpOnly Cookie；但数据库仍是 PGlite，不代替目标原生 PostgreSQL + HTTPS E2E。
- 成员敏感权限已对主题摘要、财务解释/提案和导出执行服务端拦截；家庭媒体原图业务接口尚未实现，未来接入时必须复用同一权限检查。
- 密码重置交付适配器和请求契约已自动化验证，目标服务器也已完成 PostgreSQL 与 HTTPS 部署；`notify.wbutterfly.cn` 已提交腾讯云 SES 审核。当前唯一 B-011 阻塞是审核后 DNS 验证、真实邮件 Endpoint 和专用测试邮箱读取接口。
- 2026-09-02 财务完整视觉回归已在真实登录会话下复验：23 个财务状态 × 430/390/320 共 69 张截图，全部可见、非空、无根级横向溢出且可见控件 ≥44×44pt；证据基于本地 PGlite，目标原生 PostgreSQL / 真机 / HTTPS 仍待部署闸门复验。
- 财务视觉回归覆盖导入入口与历史批次；真实文件选择 → 表头预览 → 字段映射 → 关联审核 → 提交账本、导出与撤销完整流程已由 E-116 在本地 PGlite + 真实 Cookie 会话下闭环，目标原生 PostgreSQL / 真机 / HTTPS 仍由部署闸门复验。
- 腾讯云 COS 私有桶适配已按此前要求跳过，本轮未执行真实 live smoke。
- 已在目标服务器完成本地加密备份、隔离恢复、基础 HTTPS 压测、staging 发布/回滚和 live 安全头复核；尚未完成 COS 异地备份、异常队列/超大账单/慢查询、监控告警与生产环境演练。
- 吃什么浏览器烟测验证的是 UI 行为，不验证真实推荐、数据库和 HowToCook 发布包。
- npm 漏洞审计只能覆盖已知依赖漏洞，不等于完成应用安全审计。
