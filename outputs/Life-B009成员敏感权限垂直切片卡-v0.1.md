# Life B-009 成员敏感权限垂直切片卡 v0.1

更新时间：2026-08-28

## 1. 结论

`B-009` 在当前仓库范围达到 `DONE`：家庭所有者可以按成员逐项授权或撤销 AI、家庭原图和家庭数据导出能力；非所有者默认拒绝，角色变化自动撤权，所有变更均有审计与乐观并发保护。

目标腾讯云的原生 PostgreSQL、HTTPS Secure Cookie 和共享限流仍由 `B-011`、`G-004` 与部署闸门验收，不由本切片冒充完成。

## 2. 权限矩阵

| 分组 | 能力 | 默认规则 | 当前运行时拦截 |
|---|---|---|---|
| AI | 饮食推荐 | owner 开；其它成员关 | 权限契约已建立，接入真实推荐 Provider 时强制复用 |
| AI | 主题摘要 | owner 开；其它成员关 | 主题摘要生成与提案决策 |
| AI | 财务解释 | owner 开；其它成员关 | 财务摘要、确认与撤销，同时要求财务业务权限 |
| AI | HowToCook 辅助 | owner 开；其它成员关 | 权限契约已建立，接入真实辅助 Provider 时强制复用 |
| AI | 个性化记忆 | owner 开；其它成员关 | 未授权时财务 AI 不写家庭记忆文档或记忆文件 |
| 家庭数据 | 家庭原图 | owner 开；其它成员关 | 权限契约已建立，媒体原图接口上线时强制复用 |
| 家庭数据 | 家庭数据导出 | owner 开；其它成员关 | 财务导出创建与读取，同时要求财务导出权限 |

所有者权限固定全开且不能关闭。非所有者只能查看自己的权限快照；只有所有者可以查看和修改其它成员。

## 3. 数据与 API

- 迁移：`db/migrations/0013_member_sensitive_permissions.sql`。
- 当前状态按 `household_id + user_id + capability` 唯一，包含 `enabled`、单项 `version`、授权/撤销时间和授权人。
- 只向 `life_app` 开放读取；写入、检查和角色重置均通过 `SECURITY DEFINER` 受控函数。
- RLS 和应用层同时校验家庭、成员、资源和动作。
- `GET /api/family/members/{userId}/sensitive-permissions`：owner 查看任一成员，其他成员仅查看自己。
- `PATCH /api/family/members/{userId}/sensitive-permissions`：单项授权/撤销，必须提交 `expected_version`。
- 角色变化会同时撤销财务与家庭敏感授权，并写入审计摘要。

## 4. 移动端 UX

- 从“更多 → 家庭与成员 → 管理”进入成员权限详情。
- 页面按“AI 能力 / 家庭数据”分组，不使用难以阅读的横向权限表。
- 每项使用 iOS 风格开关，但高风险变更必须先经过文字确认层。
- 成功后原位更新，不整页刷新；失败保留当前状态并给出可关闭错误反馈。
- 儿童和其它成员只能查看自己的只读授权。
- 角色确认层高于权限详情层，避免叠层拦截点击。
- 430×932、390×844、320×900 均无根级或嵌套横向溢出，所有可见控件不小于 44pt。
