# Life 财务垂直切片与 PRD 全量自检报告 v0.1

更新时间：2026-08-25

## 1. 结论先行

本轮指定顺序“P0-A 账本基础与新增记账 → 账户/分类/预算 → 实物资产 → 成员权限/审计 → 财务 AI”已经完成开发垂直切片，并通过 PostgreSQL 真实测试、契约校验、迁移烟测和移动端交互验收。

但整个 `Life-家庭生活工作台-PRD-v0.10.md` 还不能标记为“全量发布完成”。原因不是本轮切片失败，而是 PRD 明确要求的生产 AI 连接/记忆、腾讯云私有对象存储、数据清理任务、完整财务首页口径和 HowToCook 仍属于后续闸门。以下报告把“已达标”和“未达标”分开，禁止用开发 Provider 或 UI 占位替代生产能力。

## 4. UI/UX 自检

已满足的统一规范：

- 只保留移动端，不建设桌面端验收套件。
- 页面沿用淡粉/淡紫液态玻璃层级，新增入口使用上下文 Sheet，不新增一级导航。
- 新增记账作为财务主动作；账户与预算、资产、导入和 AI 解读是次级动作。
- 预算使用“一个圆、多个环、颜色表达分类、弧段表达已用、轨道表达剩余”，图例按钮与环心均可下钻。
- 账户、分类、预算、资产、权限和 AI 都使用同一 Bottom Sheet 交互语言；关闭、保存、撤销和错误状态即时反馈。
- 文字使用 `AdaptiveValue`/容器约束，长名称允许换行；关键按钮、开关、输入和来源行达到 44pt 触控目标。
- 430×932 与 320×900 已完成横向溢出、窄屏按钮、管理权限 Sheet、资产 Sheet、导入预览和财务 AI Sheet 验收。
- AI 入口明确“只读解释，不自动改账”；来源按钮可以离开 AI Sheet 并进入真实财务下钻。

## 5. 已知未闭合的 PRD 要求

这些不是本轮测试失败，而是全量 PRD 仍需继续推进的明确差距：

1. 财务首页当前正式摘要仍以收入、支出、净现金流为主；PRD 还要求净资产、账户余额、待处理项和异常提示的完整首页口径。
2. 趋势已经支持点和容器下钻，但日/周/月/季度/自定义周期切换、图例显隐和资产趋势的购买/维护/总成本切换尚未全部产品化。
3. `can_export` 已作为权限位存在，但正式导出 API、导出审计和 365 天清理任务尚未完成。
4. 原始账单当前以本地/内存对象存储完成开发验收；腾讯云 COS 私有桶、签名访问、生命周期清理、备份恢复和告警仍是发布闸门。
5. 财务 AI 当前使用 `deterministic-finance-v1` 做可重复验收；家庭独立 API 连接、密钥引用、家庭 AI 记忆文件/索引和清除审计尚未接入生产。
6. HowToCook 本地最新版解析、吃什么推荐确认、自动饮食历史和采购清单仍未进入本轮财务切片交付。
7. 全量家庭 A/B 的 AI API、记忆、向量、缓存、异步任务和备份恢复隔离测试需要在生产 AI 接入后补齐。
