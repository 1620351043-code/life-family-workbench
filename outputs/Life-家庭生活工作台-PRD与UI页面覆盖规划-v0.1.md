# Life 家庭生活工作台

## PRD 与移动端 UI 页面覆盖规划 v0.3

状态：待确认，已扩展至二级、三级页面、操作层和全工作台 AI 交互，确认后才进入视觉稿补齐与代码实现。

日期：2026-08-24

---

## 1. 本文目的

当前 UI 设计已经确定了 Life 的整体方向：移动端、淡粉淡紫 Liquid Glass、兔子助手、四个一级导航、多预算同心环和家庭主题空间。

但当前设计稿并没有覆盖 PRD 中的全部页面和状态。本文件不重新定义产品范围，而是以 [PRD v0.10](./Life-家庭生活工作台-PRD-v0.10.md) 为最高业务依据，重新整理：

1. PRD 要求哪些真实用户任务；
2. 每个任务需要哪些页面、抽屉、确认层和状态页；
3. 当前 UI/低保真已经覆盖到什么程度；
4. 哪些页面必须新增设计，哪些页面可以复用已有组件；
5. 后续代码如何与页面、数据和权限保持一致。

本文只做规划和设计基线，不修改业务代码，不开始高保真页面制作，也不开始垂直切片开发。

---

## 2. 结论先行

当前产品方向没有问题，但页面覆盖还不完整。最需要纠正的是：不能继续只围绕四个首页和几个演示页面推进，而要围绕 PRD 的完整任务闭环补齐页面。

建议采用以下产品结构：

```text
四个一级入口
├─ 空间：家庭主题协作
├─ 吃什么：推荐 → 确认 → HowToCook → 采购 → 自动沉淀行为
├─ 财务：总览 → 账单/预算/趋势/资产/导入/审核
└─ 更多：成员权限、家庭 AI、个人设置、数据与安全说明
```

必须坚持的三条原则：

- PRD 规定的功能不能因为当前没有设计稿而被删除；
- 页面不需要和 PRD 功能一一对应，可以用页面、抽屉、底部表单、确认层共同完成一个任务；
- 每一个数字、图表、列表项、AI 结果和高风险操作都必须有来源、权限、状态和下一步动作。

当前建议的设计顺序是：

```text
全局壳层与状态规范
  → 家庭空间完整闭环
  → 吃什么完整闭环
  → 财务完整闭环
  → 更多、成员权限与家庭 AI
  → 全量状态设计与跨模块回归
```

## 3. 依据与优先级

### 3.1 规范优先级

发生冲突时，按以下顺序处理：

1. 用户已经确认的产品决策；
2. PRD v0.10 的业务边界、权限、数据和验收要求；
3. 移动端信息架构与核心流程；
4. 移动端视觉与交互规范；
5. 当前低保真 HTML 和演示代码；
6. 早期图片设计稿和旧版 PRD，仅作为历史参考。

### 3.2 已确认的产品边界

- 只做移动端，不建设桌面端。
- 一级导航固定为：`空间 / 吃什么 / 财务 / 更多`。
- HowToCook 是“吃什么”的子能力，不是一级导航。
- 家庭空间以主题为核心，不建设独立收件箱、私聊和通知中心。
- “吃过什么”由系统根据高置信完成事件自动采集，只读展示，不提供手动补录。
- 每个用户只能归属于一个家庭，家庭业务数据和 AI 数据完全隔离。
- 每个家庭使用自己的 AI API 连接、记忆文件、向量命名空间和审计记录。
- 财务为 V1.0 核心能力，包含多来源账单导入、去重、银行锚点、预算、趋势、实物资产成本和可追溯下钻。
- 原始账单文件和原始导入数据保留一年。
- HowToCook 使用上游最新版下载到本地解析，运行时使用本地发布包。

## 4. 当前覆盖总览

### 4.1 覆盖等级定义

| 标记 | 含义 |
|---|---|
| 已覆盖 | 页面骨架、主要入口和核心交互方向已经存在 |
| 部分覆盖 | 有演示页面或静态占位，但缺真实页面结构、状态或数据连接 |
| 未覆盖 | PRD 已要求，但当前没有对应页面 |
| 需重设计 | 旧页面存在，但信息层级无法满足 PRD，需要重新规划 |

### 4.2 当前判断

| 一级模块 | 当前状态 | 判断 |
|---|---|---|
| 空间 | 部分覆盖 | 首页和主题详情有占位，但发布、筛选、讨论、AI 摘要和权限未形成完整闭环 |
| 吃什么 | 部分覆盖 | 推荐、确认、HowToCook、历史有骨架；搭配、搜索、菜谱库、采购清单不完整 |
| 财务 | 部分覆盖 | 多环预算和部分下钻已验证，但账户、流水、真实趋势、资产趋势、导入和交易详情未闭环 |
| 更多 | 部分覆盖 | 成员权限和 AI 设置只有展示占位，缺少真实配置和授权页面 |
| 全局状态 | 未覆盖 | 首次使用、空数据、权限、网络断开、失败、撤销和删除状态尚未系统设计 |

### 推荐的家庭空间页面结构

#### A. 家庭空间首页

页面顺序：


1. 家庭名称、成员头像组、设置入口；
2. 欢迎/行动卡：“今天，家里想一起做点什么？”；
3. 主操作：发布主题；
4. 筛选胶囊：全部、需求、想法、灵感、讨论；
5. 主题卡片流；
6. 每张卡片显示类型、标题、状态、最近更新时间、评论数、参与成员和关联内容；
7. AI 摘要只作为当前主题或当前筛选结果的上下文入口，不做全局聊天。

#### B. 发布主题页

采用单页表单或底部全屏表单：

- 主题类型：需求、想法、灵感、讨论；
- 标题；
- 正文；
- 图片/附件；
- 关联菜谱、采购清单或财务摘要；
- 保存草稿、取消、发布；
- 发布前确认家庭可见范围。

#### C. 主题详情页

页面顺序：

- 主题头部：类型、状态、作者、时间、家庭可见标识；
- 正文和附件；
- 关联内容；
- AI 摘要卡：已确认事实、未决事项、建议草稿；
- 原始评论列表；
- 评论输入框和一层回复；
- 状态变更入口；
- 归档前确认。

### 推荐的吃什么页面结构

#### A. 吃什么首页

首屏只解决“今天吃什么”：

- 当前餐次和家庭上下文；
- 推荐菜谱卡；
- 推荐理由：长期习惯、最近少吃、当前时间、预算或食材重叠；
- 智能搭配入口；
- 搜索菜谱入口；
- 吃过什么和采购清单作为次级入口。

#### B. 智能搭配页

输入项按重要程度分组：

1. 人数；
2. 餐量；
3. 今天想吃/不想吃；
4. 时间、预算和忌口；
5. 生成搭配。

结果页展示主菜、配菜、主食和替代方案，支持一键进入采购清单，但仍然需要经过确认层。

#### C. 菜谱搜索页

搜索范围：菜名、食材、口味、耗时、难度、分类。搜索结果不直接绕过确认流程，选中后进入统一的推荐选择确认页。

#### D. 吃过什么页

这是行为结果展示页，不是饮食日志编辑器。支持：

- 按日期筛选；
- 按餐次筛选；
- 按家庭成员筛选；
- 进入对应 HowToCook 菜谱；
- 显示记录来源和置信度说明。

不支持手动新增、修改、补录或人为标记“已吃过”。

#### E. HowToCook 菜谱详情页

页面层级：

- 菜谱封面、名称、时间、人数和来源；
- 食材列表和份数调整；
- 工具；
- 步骤；
- AI 步骤解释和替代建议；
- 开始烹饪；
- 生成/更新采购清单。

AI 内容必须和上游原始步骤区分显示，不能把 AI 建议伪装成上游原文。

#### F. 采购清单页

- 按食材合并；
- 显示来源菜谱；
- 支持数量和单位；
- 勾选完成；
- 标记“家中已有”；
- 关联回主题或家庭空间；
- 不直接改写原始菜谱。

## 5.3 财务

财务必须按照“总览可解释、明细可追溯、导入可审核”的标准设计。当前财务首页的多环预算视觉可以保留，但不能把首页圆环误认为已经覆盖完整财务功能。

|---|---|---|---|
| 财务首页 | 财务总览页 | 部分覆盖 | 补回净资产、账户余额、收入、支出、净现金流及待处理摘要 |
| 账户与资产 | 账户/资产列表页 | 未覆盖 | 新增账户余额和实物资产入口 |
| 账户详情 | 账户详情页 | 未覆盖 | 余额快照、账单、变更和权限 |
| 收支明细 | 统一账单页 | 未覆盖 | 支持筛选、分页、来源和批量处理 |
| 全部流水 | 全部流水页 | 未覆盖 | 支持父子结算、重复关系和来源链路 |
| 新增记账 | 新增记账底部表单 | 未覆盖 | 支持收入、支出、转账和保存撤销 |
| 多环预算 | 财务首页/预算页 | 部分覆盖 | 保留圆环，新增预算管理和全部分类页 |
| 收支趋势 | 财务首页/趋势详情 | 部分覆盖 | 改为真实数据驱动，支持日/周/月/自定义 |
| 实物资产成本趋势 | 资产详情/趋势页 | 部分覆盖 | 从列表升级为真正趋势图和资产事件链 |
| 导入账单 | 导入向导 | 部分覆盖 | 接通真实文件、表头识别、字段映射和预览 |
| 关联审核 | 关联审核页 | 部分覆盖 | 补齐重复、父子结算、退款、手续费和拆分规则 |
| 交易详情 | 交易详情页 | 未覆盖 | 增加银行锚点、支付平台明细和来源文件 |
| 财务设置与审计 | 财务设置页 | 未覆盖 | 分类、来源、权限、保留期、操作记录和导出说明 |

### 推荐的财务首页结构

#### A. 周期与数据状态

- 当前家庭；
- 当前周期；
- 数据更新时间；
- 待处理数量；
- 网络/离线状态。

#### B. 摘要卡片

至少展示：

- 净资产；
- 账户余额；
- 当前收入；
- 当前支出；
- 净现金流。

每张卡片都要显示周期、金额、变化和 `drilldown_ref` 对应的明细入口。

#### C. 多预算同心环

继续使用已确认的视觉规则：

- 一个共同圆心；
- 每个分类一个环；
- 饱和色表示已使用；
- 同色浅轨道表示剩余；
- 圆心进入全部预算明细；
- 环本身、分类项和“查看全部”都可进入明细；
- 1–6 类在首屏自适应；7 类以上进入全部分类抽屉。

重要补充：环的 SVG 命中区域也必须可点击，不能只依赖圆环下方的分类按钮。

#### D. 收入/支出趋势

- 日、周、月、自定义周期；
- 收入、支出和净现金流图例；
- 图例可以隐藏/显示对应曲线；
- 点击数据点先展示周期摘要，再进入账单明细；
- 图表本身可以进入当前周期全部账单；
- 空数据、部分数据、数据延迟和异常状态必须有明确表现。

#### E. 实物资产成本趋势

趋势至少包含：

- 购买成本；
- 维护成本；
- 回收金额；
- 净现金成本。

点击任意时间点进入资产事件和关联账单；点击某项资产进入资产详情。

#### F. 待处理与最近流水

- 待解析导入；
- 待确认表头；
- 待字段映射；
- 待关联审核；
- 待提交账本；
- 最近账单和异常账单。

### 推荐的财务导入向导

导入必须设计成一个可恢复的分步流程，而不是一个上传按钮：

```text
选择文件
  → 文件安全检查与哈希
  → 识别文件格式 / 编码 / Sheet
  → 自动识别表头行
  → 用户确认表头和数据区域
  → 统一字段映射
  → 预览解析结果和错误
  → 识别来源关系与重复候选
  → 关联审核
  → 确认写入统一账本
  → 统计、预算、趋势刷新
```

必须明确展示：

- 识别到第几行为表头；
- 读取了哪一个 Sheet；
- 解析了多少行；
- 哪些行失败；
- 哪些记录为银行锚点；
- 哪些记录只保留为支付平台详细信息；
- 哪些记录不会计入正式账本；
- 原始文件保留到什么日期。

### 推荐的交易详情页

交易详情是财务可追溯性的核心页面，至少包括：

- 正式账本金额、方向、日期、分类和账户；
- 银行锚点来源；
- 微信/支付宝等平台详细记录；
- 原始文件名称和导入批次；
- 关联/重复/父子结算关系；
- 原始字段与标准化字段；
- 审核记录；
- 可执行的撤销或修正动作。

正式账本只统计一次，来源明细保留一年并可审计。

| 个人设置 | 个人设置页 | 未覆盖 | 登录安全、推荐偏好开关、数据说明 |

### 家庭成员权限页

- 成员头像、昵称、家庭角色；
- 财务权限组；
- AI 权限组；
- 儿童/成年成员标识；
- 最近授权记录；
- 撤销权限入口。

### 家庭 AI 设置页

页面分成四块：

1. 连接：提供商、Endpoint、模型策略、连接测试、轮换和禁用；
2. 使用范围：吃什么、家庭主题、财务解释、HowToCook；
3. 记忆：记忆文件、结构化事实、向量索引、自动清理；
4. 审计：调用时间、用途、来源、结果和错误。

## 6. 全局页面状态和交互规范

PRD 要求每个 P0 页面都设计完整状态。后续所有页面至少要有以下状态：

| 状态 | 设计要求 |
|---|---|
| 首次使用 | 解释页面用途，只提供一个主要开始动作 |
| 加载中 | 使用稳定骨架，不闪烁，不改变主要布局 |
| 有数据 | 显示来源、更新时间和主要动作 |
| 空数据 | 解释为什么为空，提供下一步动作 |
| 无搜索结果 | 保留搜索条件，提供修改和清空入口 |
| 处理中 | 显示阶段、进度和可离开后的恢复方式 |
| 成功 | 给出明确结果和下一步 |
| 失败 | 说明用户可理解的原因，提供重试或返回 |
| 网络断开 | 区分已保存、未保存和可离线查看内容 |
| 无权限 | 不泄露资源标题、金额、正文或摘要 |
| 资源被删除 | 说明资源已不可用，提供返回上级入口 |
| 撤销 | 展示撤销结果，不把撤销伪装成删除 |
| 权限变化 | 页面刷新后重新校验，不继续展示过期数据 |

### 全局交互原则

- 触控目标不小于 44×44px；
- 页面返回遵循 iOS 直觉：返回按钮、边缘右滑和底部表单下滑关闭；
- 主要动作只有一个视觉主按钮；
- 高风险写入统一采用“预览 → 确认 → 结果”；
- AI 建议统一显示“AI 建议/摘要”、来源、时间和确认状态；
- 玻璃效果服务于层级，不覆盖文字、不降低对比度、不用装饰替代状态；
- 页面内的卡片、圆环、趋势点和列表项都必须给出即时按压反馈；
- 所有异步操作都要有防重复提交和失败恢复。

## 7. 后续代码设计必须遵守的对齐规则

### 7.1 页面不是数据源

UI 页面不能使用硬编码账单、预算、趋势或主题作为最终实现。页面只负责展示服务端返回的领域模型和状态。

禁止以下做法：

- 客户端自行拼接财务筛选条件；
- 用固定 SVG 坐标代表真实趋势数据；
- 用固定主题详情代替主题 ID；
- 用本地 fallback 冒充 AI 摘要结果；
- 上传页面显示示例文件但不接入真实解析器。

### 7.2 页面模型必须带状态和来源

每个页面模型至少要能表达：

```text
data
loading
empty
error
permission
updated_at
source
drilldown_ref
available_actions
```

财务首页模型必须覆盖 PRD 中的全部摘要、预算、趋势、资产、待处理和最近流水，不允许为了视觉简洁删除业务必需指标。

### 7.3 路由必须对应真实资源

以下资源需要真实 ID 和真实接口：

- household_id；
- topic_id；
- recipe_id；
- shopping_list_id；
- account_id；
- transaction_id；
- budget_id；
- import_batch_id；
- asset_id；
- ai_insight_id；
- ai_action_proposal_id。

页面跳转不能只改变一个本地 route 字符串而继续渲染固定内容。

### 7.4 领域边界

后续建议按以下领域拆分代码：

```text
identity / household
topics
food / recipes / cooking / shopping
finance / ledger / budgets / assets / imports
ai / memory / consent / audit
shared UI / navigation / states / drilldown
```

家庭主题、饮食行为、财务账本和 AI 记忆必须分别拥有自己的权限检查和 `household_id` 过滤，不把所有逻辑堆到一个页面文件里。

## 11. 深层页面规划方法

为了避免后续只设计首页、不设计真实操作页面，所有功能统一拆成五层：

```text
L0 模块入口
  → L1 任务页面
  → L2 资源详情
  → L3 操作层/确认层
  → L4 结果层/异常层
```

### 11.1 五层的职责

| 层级 | 作用 | 典型形式 |
|---|---|---|
| L0 | 一级模块入口 | 底部导航和四个首页 |
| L1 | 完成一个主要任务 | 发布主题、菜谱搜索、账单导入 |
| L2 | 查看一个具体资源 | 主题详情、菜谱详情、交易详情 |
| L3 | 修改、确认或授权 | 底部表单、抽屉、确认弹层、全屏步骤 |
| L4 | 告知操作结果或处理异常 | 成功页、失败页、重试页、撤销结果 |

### 11.2 深层页面设计原则

- 首页只做摘要和入口，不承载完整编辑流程。
- 详情页必须围绕一个真实资源 ID 展示，不能用固定演示内容替代。
- 修改和高风险动作优先使用底部表单或确认层，避免用户迷失在多级页面中。
- 需要长时间处理的任务使用独立进度页，并支持离开后恢复。
- 任何深层页面都必须有明确的返回目标，不允许返回后丢失用户已填写内容。
- 深层页面不新增一级导航，统一从所属模块返回。
- 视觉稿中出现的每个入口，都必须能够映射到 PRD 功能、页面路由或操作层。

## 19. 全工作台 AI 交互总设计

### 19.1 AI 的产品定位

小兔子不是一个独立的聊天机器人，也不是一个拥有全部权限的自动管家。它是 Life 的“上下文智能操作层”：

```text
用户正在做什么
      ↓
小兔子理解当前页面、家庭、资源和权限
      ↓
给出解释、建议、摘要或可执行草案
      ↓
用户查看依据并确认
      ↓
系统执行可审计、可撤销的动作
```

小兔子要减少用户的重复操作和理解成本，但不能替用户做不可逆决定，也不能把推断伪装成事实。

### 19.2 AI 交互的四个层级

| 层级 | 用户感受 | 小兔子做什么 | 是否改变正式数据 |
|---|---|---|---|
| L1 陪伴提示 | “它注意到了当前情况” | 提醒、解释当前页面、提示下一步 | 否 |
| L2 上下文建议 | “它帮我分析了一下” | 推荐、摘要、趋势解释、候选关联 | 否 |
| L3 行动草案 | “它已经准备好了” | 生成待确认的主题、分类、采购清单或关联方案 | 否，需确认 |
| L4 确认执行 | “我决定让它做” | 执行已确认的可逆动作并记录审计 | 是，需权限 |

所有 AI 交互都必须明确处于哪一层。小兔子不能从 L1 直接跳到 L4。

### 19.3 全局原则

- 小兔子始终知道自己处于哪个家庭、哪个成员权限和哪个业务上下文。
- 默认只读取当前页面和当前任务所需的数据，不主动扫描整个家庭。
- 跨模块读取必须通过明确的关联入口或用户选择，不允许静默扩展上下文。
- 任何写入、修改、合并、发布、授权、清除和导出都必须先生成行动草案。
- AI 输出必须显示来源、生成时间、数据范围和建议/事实性质。
- AI 失败时退回确定性规则或原始数据，不显示伪造的“智能结果”。
- 小兔子的情绪和动画用于反馈状态，不用于掩盖等待、错误或权限限制。
- AI 不作为一级导航，不新增聊天中心，不生成收件箱和私聊体系。

## 20. 小兔子统一入口设计

### 20.1 入口形态

推荐采用“一个全局入口 + 多个上下文入口”的组合：

```text
全局小兔子入口
  ├─ 页面级 AI 面板
  ├─ 页面内 AI 洞察卡
  ├─ 具体资源上的 AI 操作
  └─ AI 设置、记忆和审计
```

### 20.2 全局入口位置

小兔子不放进底部导航，也不悬浮在底部导航正上方。推荐放在每个页面的导航栏右侧：

- 44×44px 触控区域；
- 兔子头像作为主视觉；
- 默认显示小头像，不占用页面主要内容；
- 有待确认 AI 建议时显示小圆点，不使用高频跳动；
- 正在处理时显示轻量状态环；
- 无家庭 AI 连接时显示可识别的降级标识；
- 小兔子入口与页面标题、返回按钮保持足够间距。

页面头部示意：

```text
‹ 返回        页面标题                         🐰
```

首页内容中的大兔子形象可以继续作为情绪陪伴和品牌展示，但只有导航栏小兔子是稳定的交互入口。大兔子不承担隐藏按钮功能。

### 20.3 小兔子入口的四种状态

| 状态 | 视觉反馈 | 用户含义 |
|---|---|---|
| 安静 | 兔子头像，无徽标 | 当前没有需要处理的 AI 事项 |
| 有建议 | 头像旁一个小圆点 | 当前上下文有新的 AI 建议或摘要 |
| 处理中 | 头像外圈缓慢进度环 | AI 正在生成结果，用户可以继续浏览 |
| 待确认 | 头像旁柔和的确认标记 | 有行动草案等待用户确认 |
| 降级 | 低对比度状态标识 | 当前使用规则能力或原始数据 |
| 无权限/不可用 | 不展示敏感提示，只显示普通入口 | 点击后解释可用范围，不泄露数据 |

### 20.4 入口触控和手势

- 单击：打开当前上下文的 AI 面板；
- 再次单击：关闭面板或回到原页面；
- 面板上滑：展开为接近全屏的上下文工作区；
- 面板下滑：收起到页面底部，不丢失已生成内容；
- 边缘右滑：返回上一个页面，不执行 AI 动作；
- 长按不绑定高风险动作，避免误触；
- 不使用摇一摇、连续点击、双指手势等不可发现交互。

## 21. 小兔子 AI 面板

### 21.1 面板定位

小兔子面板是“当前上下文工作区”，不是全局聊天窗口。面板打开后必须显示当前上下文：

```text
小兔子
当前在：家庭空间 · 周末家庭活动
我只会使用：当前主题、已授权成员评论和关联内容
```

### 21.2 面板结构

```text
┌─────────────────────────┐
│ 🐰 小兔子        收起   │
│ 当前上下文和数据范围     │
├─────────────────────────┤
│ 当前建议/摘要卡           │
│ 来源、时间、置信度        │
│ 查看依据 / 生成行动草案   │
├─────────────────────────┤
│ 快捷动作                  │
│ [帮我总结] [解释一下]     │
│ [给我建议] [查看依据]     │
├─────────────────────────┤
│ 输入当前问题……       发送 │
└─────────────────────────┘
```

面板内容顺序：

1. 当前页面和数据范围；
2. 当前最重要的 AI 洞察；
3. 与当前任务匹配的快捷动作；
4. 用户问题输入；
5. 结果来源、状态和确认操作。

### 21.3 快捷动作必须随上下文变化

小兔子不能在所有页面显示同样的按钮。

| 当前页面 | 快捷动作 |
|---|---|
| 家庭空间首页 | 总结最近主题、找出待处理事项、生成主题建议 |
| 主题详情 | 总结讨论、列出未决事项、拟一份回复草稿、查看原始评论 |
| 吃什么首页 | 为什么推荐、重新推荐、智能搭配、查看推荐依据 |
| 推荐确认 | 检查食材冲突、调整份数、生成采购清单、解释选择 |
| HowToCook | 解释当前步骤、换算份数、给出替代建议、报告完成 |
| 吃过什么 | 解释记录来源、查看推荐影响、筛选自动记录 |
| 财务首页 | 解释趋势、查看预算风险、查看待处理导入、生成本月摘要 |
| 交易详情 | 解释来源、查看关联关系、提出分类建议、检查重复 |
| 导入审核 | 解释候选关系、显示匹配依据、生成审核草案 |
| 实物资产 | 解释成本变化、查看异常事件、生成资产摘要 |
| 更多/AI 设置 | 查看连接状态、查看记忆范围、查看审计、清除记忆 |

### 21.4 自然语言输入的边界

允许用户在当前面板中直接提问，例如：

- “为什么推荐这道菜？”
- “把这几条讨论总结一下。”
- “这笔账为什么被认为可能重复？”
- “帮我看看这个月哪里超预算了。”

但输入框必须保持当前上下文，不提供没有边界的“问整个家庭所有事情”。用户需要跨模块时，系统先展示将要读取的范围，再要求确认：

```text
你正在从“财务首页”查看家庭主题中的采购计划。
将读取：财务摘要 + 已授权主题关联内容。
[继续] [取消]
```

## 22. AI 结果卡设计

### 22.1 统一结果卡结构

所有 AI 结果都使用统一结构，不因模块不同而隐藏关键信息：

```text
AI 建议/摘要
一句话结论
依据：3 条评论 · 近 30 天完成记录 · 导入批次 #123
生成时间：刚刚
置信度：高/中/低
数据范围：当前家庭 · 当前授权成员

[查看依据] [生成行动草案]
```

### 22.2 结果类型

| 类型 | 用途 | 默认动作 |
|---|---|---|
| AI 摘要 | 压缩当前内容 | 展开来源 |
| AI 解释 | 解释某个数字、推荐或判断 | 查看依据 |
| AI 推荐 | 给出候选方案 | 选择一个或重新生成 |
| AI 候选关联 | 提出重复、父子结算等关系 | 查看候选详情 |
| AI 行动草案 | 准备一次可执行变更 | 预览变更 |
| AI 风险提示 | 说明权限、数据或业务风险 | 查看风险说明 |
| AI 降级结果 | 模型不可用时返回规则/原始信息 | 查看原始数据 |

### 22.3 来源和依据

“查看依据”展开为来源抽屉，而不是直接显示一大段模型思考过程。来源抽屉显示：

- 来源对象类型和 ID；
- 来源摘要或允许展示的原文；
- 来源时间；
- 数据是否经过权限过滤；
- AI 使用的规则/模型版本；
- 当前判断是事实、行为还是推断。

不向用户展示内部隐式推理过程，不使用“模型思考内容”作为产品功能。产品展示的是可验证的来源和简明理由。

## 23. AI 行动草案和确认机制

### 23.1 所有写入都先变成草案

AI 不直接写入正式数据，必须先生成 `AIActionProposal`：

```text
AI 识别/建议
  → 行动草案
  → 变更预览
  → 用户确认
  → 权限二次校验
  → 执行
  → 结果和审计
```

### 23.2 行动草案卡

```text
小兔子准备了一个建议
动作：将 2 条来源记录关联为同一笔账单
影响：正式账本计入 1 次，保留 2 条来源明细
依据：金额、时间、银行流水号和商户信息
风险：中

[查看变更前后] [拒绝] [确认执行]
```

### 23.3 必须确认的动作

- 发布或修改家庭主题；
- 生成或修改采购清单；
- 修改家庭偏好；
- 修改预算；
- 分类、合并、拆分或关联财务数据；
- 写入导入账单；
- 撤销账单或导入；
- 授予或撤销成员权限；
- 清除记忆、删除文件或删除家庭数据；
- 任何跨模块关联。

### 23.4 不需要确认的动作

以下动作只读，不改变正式数据：

- 解释当前页面；
- 展示推荐候选；
- 展示主题摘要；
- 展示预算趋势解释；
- 展示 HowToCook 步骤解释；
- 展示来源和审计信息。

### 23.5 确认结果

确认后的结果必须显示：

- 执行动作；
- 实际改变的资源；
- 未执行或跳过的部分；
- 是否可以撤销；
- 审计 ID；
- 失败时的重试方式。

## 24. 四个模块的 AI 具体交互

## 24.1 家庭空间：小兔子是讨论整理者

### 主要能力

- 总结主题正文和评论；
- 区分已确认事实、不同意见和未决事项；
- 生成行动建议草稿；
- 提议主题状态；
- 根据主题关联菜谱、采购清单或财务摘要；
- 生成回复草稿，但不能自动发布。

### 推荐流程

```text
进入主题详情
  → 点击小兔子
  → 选择“总结讨论”
  → 展示摘要、来源评论和未决事项
  → 用户点击“生成行动草案”
  → 预览主题状态/回复/关联内容变化
  → 用户确认或拒绝
```

### 约束

- 不能把“建议”改写成主题正文；
- 不能把成员未确认的意见写成共识；
- 不能自动发布回复；
- 主题归档后只能摘要和检索，不能继续生成写入动作；
- 儿童成员的内容必须按授权范围进入上下文。

## 24.2 吃什么：小兔子是家庭饮食决策助手

### 主要能力

- 结合家庭长期行为提供推荐；
- 解释推荐理由；
- 根据人数、餐量、时间、预算和忌口搭配一餐；
- 检查菜谱之间的食材冲突和重复；
- 进行份数换算；
- 提供合理替代建议；
- 将确认结果生成采购清单。

### 推荐流程

```text
吃什么首页
  → 小兔子“为什么推荐”
  → 展示推荐依据
  → 用户选择或重新推荐
  → 选择确认
  → 小兔子检查冲突/份数
  → 用户确认
  → HowToCook/采购清单
```

### 约束

- 推荐只是候选，不自动确认；
- 用户未明确选择时，不生成采购清单；
- 浏览、收藏、点击和查看菜谱不能直接生成“吃过什么”；
- 食品安全和医学相关内容必须降级为谨慎提示，不伪装成专业结论；
- HowToCook 上游原始步骤优先，AI 解释单独标识。

## 24.3 财务：小兔子是解释和审核助手

### 主要能力

- 解释收入、支出和净现金流趋势；
- 解释预算超支和分类变化；
- 提示实物资产成本异常；
- 辅助账单字段映射；
- 提出重复、父子结算、退款、手续费和拆分候选；
- 生成财务摘要；
- 在交易详情中解释来源关系。

### 推荐流程：预算解释

```text
点击预算环
  → 进入分类账单
  → 点击小兔子“解释本月变化”
  → 展示金额变化、来源分类和时间范围
  → 查看账单依据
  → 不产生任何写入
```

### 推荐流程：导入审核

```text
导入关联审核
  → 小兔子显示候选关联
  → 点击某候选
  → 展示匹配依据和风险
  → 生成关联行动草案
  → 用户确认
  → 服务端再次校验
  → 写入关系并保留来源明细
```

### 约束

- AI 不能自动把银行和支付平台账单合并进正式账本；
- AI 不能绕过财务权限；
- AI 不能改变金额、日期和来源原文；
- AI 不能把低置信候选隐藏为确定结果；
- 所有财务建议必须能回到具体交易或来源记录。

## 24.4 更多：小兔子是家庭 AI 管理员

在“更多”中，小兔子不提供泛化聊天，而提供清晰的管理能力：

- 当前家庭 AI 是否已配置；
- 哪些能力正在使用 AI；
- 哪些成员被授权；
- 已经形成了哪些记忆；
- 记忆来自哪些事件；
- 最近调用了哪些数据；
- 如何清除、禁用和撤回。

## 25. AI 记忆交互设计

### 25.1 记忆分为四类

| 类型 | 示例 | 默认处理 |
|---|---|---|
| 明确事实 | “孩子不吃辣” | 需标注来源，可查看和撤回 |
| 行为事件 | 完成烹饪、确认账单 | 自动记录，按家庭隔离 |
| 推断偏好 | “可能偏好快手菜” | 显示置信度和有效期，不当作事实 |
| 临时上下文 | 当前正在看的交易 | 默认不进入长期记忆 |

### 25.2 记忆入口

小兔子面板中的“已记住”入口只在存在可展示记忆时出现。用户可以查看：

- 记忆内容；
- 类型；
- 来源事件；
- 形成时间；
- 有效期；
- 置信度；
- 使用范围；
- 删除/撤回动作。

### 25.3 记忆确认策略

- 行为事件可以自动记录，但不能自动提升为高敏感事实；
- 推断偏好必须标记“可能”，并允许用户关闭个性化推荐；
- 财务原始数据不直接写入长期偏好记忆；
- 儿童相关记忆默认需要家庭所有者授权；
- 清除记忆必须区分单条清除、某一类清除和全量清除；
- 清除后要显示结构化记录、文件、向量、缓存和异步任务的处理状态。

---

## 26. AI 权限和家庭隔离交互

### 26.1 每次调用前的权限检查

```text
用户身份
  → 当前家庭归属
  → 当前页面资源
  → 成员授权范围
  → AI 能力权限
  → 家庭 AI 连接状态
  → 生成结果或降级
```

任意一步无法确认，必须拒绝或降级，不允许猜测家庭、不允许使用默认连接。

### 26.2 权限不足时的小兔子表现

小兔子不能说出用户无权查看的资源名称、金额、主题内容或记忆内容。建议表现：

```text
这项 AI 能力暂时不能使用
需要家庭所有者授权“财务解释”后才能继续。

[查看授权说明]
```

### 26.3 家庭 AI 未配置时

```text
当前家庭还没有配置专属 AI 连接
我可以继续提供规则推荐、原始账单和标准化菜谱内容。
配置后才能使用个性化摘要和长期习惯推荐。

[去配置] [继续使用基础能力]
```

不能自动回退到系统默认 API 或其它家庭的连接。

## 27. AI 加载、失败和降级状态

| 状态 | 小兔子表现 | 页面动作 |
|---|---|---|
| 排队 | 轻量等待状态 | 可继续浏览 |
| 生成中 | 进度环/阶段文字 | 可取消或收起 |
| 成功 | 结果卡和来源 | 查看依据/生成草案 |
| 部分成功 | 标出完成和缺失部分 | 查看原始数据 |
| 模型不可用 | 明确“使用基础能力” | 继续使用规则结果 |
| 家庭 AI 未配置 | 解释未配置原因 | 去设置或跳过 |
| 超时 | 保留问题和上下文 | 重试 |
| 权限不足 | 不透露敏感数据 | 查看授权说明 |
| 内容被删除 | 显示资源不可用 | 返回上级 |
| 结果过期 | 显示生成时间和刷新入口 | 重新生成 |

小兔子在失败状态下不能只显示“出错了”，也不能使用旧结果伪装成刚刚生成的结果。

## 28. AI 视觉和动效规范补充

### 28.1 兔子形象的状态表达

| 情绪/动作 | 产品语义 | 使用场景 |
|---|---|---|
| 安静微笑 | 待命 | 普通页面 |
| 轻微眨眼 | 有新建议 | 建议卡可查看 |
| 轻微思考 | 正在处理 | AI 生成中 |
| 举起小卡片 | 待确认 | 有行动草案 |
| 点头 | 执行成功 | 操作完成 |
| 耳朵放低 | 处理失败/不可用 | 错误或降级 |
| 盾牌/锁定 | 权限限制 | 无权限或未配置 |

动效规则：

- 默认动画短、慢、低干扰；
- 不使用持续跳动、强闪烁或遮挡内容的动画；
- 支持“减少动态效果”；
- 财务页面优先使用状态环和微动效，不使用夸张表情；
- 高风险确认不能依靠兔子表情传达，必须同时显示文字和按钮。

### 28.2 颜色和层级

- 小兔子入口沿用淡粉淡紫与蓝色主操作色；
- AI 建议使用柔和紫色或淡蓝色容器，与正式数据卡区分；
- AI 风险使用橙色，错误使用红色，成功使用绿色；
- AI 颜色不能替代“建议/事实/已执行”文字状态；
- AI 面板的玻璃层级不能盖住底部导航和系统安全区域。

## 29. AI 页面与接口登记

### 29.1 页面/操作层

| 页面/层 | 入口 | 主要职责 | 是否写入 |
|---|---|---|---|
| AI 面板 | 全局小兔子 | 当前上下文问答、快捷动作和洞察 | 默认否 |
| AI 来源抽屉 | 结果卡“查看依据” | 展示来源、时间和版本 | 否 |
| AI 行动草案 | 结果卡“生成草案” | 展示即将发生的变更 | 否 |
| AI 确认层 | 草案“确认执行” | 二次校验并执行 | 是，需权限 |
| AI 记忆页 | 更多/家庭 AI | 查看、撤回和清除记忆 | 是，需权限 |
| AI 连接页 | 更多/家庭 AI | 配置、测试、轮换和禁用连接 | 是，所有者 |
| AI 审计页 | 更多/家庭 AI | 查看调用和执行记录 | 否 |

### 29.2 建议的服务端契约

后续 API 设计应至少能够表达以下对象：

```text
AIContext
AIInsight
AIActionProposal
AIMemoryFact
AIMemoryArtifact
AIConsentPolicy
AIExecutionLog
HouseholdAIConnection
```

建议的职责边界：

- `AIContext`：当前家庭、成员、页面、资源和授权范围；
- `AIInsight`：只读推荐、解释和摘要；
- `AIActionProposal`：待确认的写入动作；
- `AIMemoryFact`：事实、行为或推断记忆；
- `AIMemoryArtifact`：家庭 AI 记忆文件及清理状态；
- `AIConsentPolicy`：成员和能力授权；
- `AIExecutionLog`：模型/规则版本、用途、结果和审计；
- `HouseholdAIConnection`：家庭专属连接配置和状态。

任何 AI 响应至少需要携带：

```text
household_id
context_id
source_refs
created_at
expires_at
confidence
result_type
permission_scope
model_or_rule_version
audit_id
```

### 29.3 客户端禁止事项

- 不在客户端保存家庭 API 密钥；
- 不在客户端拼接家庭 AI 上下文；
- 不把 AI 结果直接当作正式业务数据；
- 不绕过服务端执行确认动作；
- 不把家庭记忆存进全局 localStorage 或共享缓存；
- 不用前端隐藏按钮代替权限检查；
- 不把一个家庭的 AI 结果缓存给另一个家庭。

## 30. AI 设计稿交付范围

AI 相关设计不能只画一个兔子按钮，至少需要完成以下页面和状态：

- 处理中；
- 待确认；

- 家庭空间上下文；
- 吃什么上下文；
- 财务上下文；
- 更多/设置上下文；
- 空结果；
- 生成中；
- 失败重试；
- 自然语言输入；

## 31. AI 进入代码前的验收闸门

在 AI 进入代码实现前，必须确认：

- 小兔子是统一入口，但不是一级导航；
- AI 面板始终显示当前家庭、页面和数据范围；
- 每个模块的快捷动作与当前上下文匹配；
- AI 只读建议与 AI 写入草案有明显区别；
- 所有写入都有预览、确认、权限校验、结果和审计；
- 主题、饮食、财务和更多页面都定义了 AI 的具体职责；
- 家庭 AI 连接、记忆、缓存、向量和审计都按家庭隔离；
- 儿童权限和财务权限不会被 AI 绕过；
- 模型不可用时有规则或原始数据降级；
- 结果卡能展示来源、时间、置信度和版本；
- AI 不生成独立聊天中心、收件箱或私聊；
- 视觉稿包含入口、面板、结果卡、行动草案和全部关键状态；
- API 和数据库契约已经能承载 `AIInsight`、`AIActionProposal`、`AIMemoryFact` 和审计对象。

### 推荐的 AI 第一条垂直切片

```text
主题详情
  → 点击小兔子
  → 生成主题摘要
  → 查看原始评论来源
  → 生成行动草案
  → 用户确认/拒绝
  → 展示审计结果
```

这条切片最适合验证小兔子入口、上下文边界、AI 结果卡、来源展示、确认机制、家庭隔离和失败降级。确认完成后，再将同一套 AI 交互骨架复用到吃什么和财务。

本 AI 交互设计确认前，不生成视觉稿，不新增 AI 路由，不修改现有代码。
