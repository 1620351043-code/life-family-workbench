# Life 移动端总体 UI 设计系统 v0.1

状态：总体设计系统收口基线

更新时间：2026-08-25

## 1. 设计系统结论

Life 的总体视觉方向确定为“温柔家庭感 + iOS 层级秩序 + 轻量 Liquid Glass”。

核心规则不是让每个区域都像玻璃，而是把界面分成清晰的功能层和内容层：

```text
环境层：淡紫与淡粉的柔和氛围背景
内容层：稳定、可读、较不透明的标准表面
功能层：导航、主要操作、Sheet 使用 Liquid Glass
反馈层：状态、错误、成功和 AI 提案的即时反馈
```

Apple 的 Liquid Glass 指南明确建议：Liquid Glass 用于导航和控件等功能层，不要在内容层大面积使用；内容层应使用标准材料保持层级和可读性。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)  
交互遵循标准点击、滑动、拖动和长按，并为动作提供即时反馈，不创造不必要的专属手势。[Apple Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures/) 

## 2. 视觉基线

### 2.1 色彩角色

颜色按“角色”管理，不允许页面自行挑选近似颜色。

| 角色 | Token | 值 | 使用规则 |
|---|---|---:|---|
| 页面底色 | `--life-bg-base` | `#F7F2FB` | 所有页面的稳定底色 |
| 淡紫氛围 | `--life-bg-lavender` | `#DCD8FF` | 环境层，不承载文字 |
| 淡粉氛围 | `--life-bg-blush` | `#FFE1E2` | 环境层，不承载文字 |
| 主文字 | `--life-text-primary` | `#252642` | 标题、金额、核心事实 |
| 次文字 | `--life-text-secondary` | `#686D8C` | 解释、描述、辅助信息 |
| 弱文字 | `--life-text-tertiary` | `#9297AE` | 时间、提示和非核心信息 |
| 主操作 | `--life-accent` | `#5B72F4` | 主要按钮、选中态、链接 |
| 主操作深色 | `--life-accent-strong` | `#465BD1` | 按下态和高对比文字 |
| 成功 | `--life-success` | `#2D9B72` | 文字、图标和轻量背景共同表达 |
| 警告 | `--life-warning` | `#C88628` | 预算接近上限、待处理 |
| 危险 | `--life-danger` | `#C94D69` | 错误、超预算和不可逆提示 |
| 内容表面 | `--life-surface-content` | `rgba(255,255,255,.78)` | 内容卡片，保持稳定可读 |
| 内容强调表面 | `--life-surface-elevated` | `rgba(255,255,255,.90)` | 重要卡片和表单区域 |
| 功能玻璃 | `--life-material-functional` | `rgba(255,255,255,.58)` | 底部导航、Sheet、浮动控件 |
| 边界 | `--life-line` | `rgba(112,105,171,.16)` | 内容边界和分隔线 |

淡粉和淡紫只负责环境氛围；正文、金额、按钮文字不能依赖背景颜色获得对比度。

### 2.2 模块语义色

| 模块 | Token | 值 |
|---|---|---:|
| 家庭空间 | `--life-space-blue` | `#6076E9` |
| 吃什么 | `--life-food-orange` | `#E99B36` |
| 财务 | `--life-finance-green` | `#2DAD78` |
| 小兔子 AI | `--life-ai-violet` | `#8968E8` |

模块色只表达模块身份，不替代成功、警告、危险等状态色。

### 2.3 预算环色

预算环使用固定的可区分颜色，并同时显示分类名、已用金额、余额和比例：

`#F06F8C / #E99B36 / #6488F0 / #936FE7 / #3EB391 / #4CAFC1`

超过 100% 时叠加危险状态、缺口文本和纹理/线型变化，不能只把整环变成红色。

## 3. 尺寸、排版与布局

### 3.1 间距

采用 4pt 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32`。

- 页面内容水平边距：16pt。
- 主卡片内边距：16–20pt。
- 主要区块间距：24pt。
- 列表项间距：8–12pt。
- 可点击元素之间至少保留 8pt 空隙。

### 3.1.1 自适应容器与多容器排版

页面不能依赖固定列数、固定宽度或绝对定位来容纳业务数据。所有可增长的内容区必须使用自适应布局：

- 卡片、快捷入口、预算分类和筛选项使用 `auto-fit + minmax()` 或等价的容器查询布局；优先自动换列，其次才是纵向堆叠。
- 内容容器必须设置 `min-width: 0`，文字容器必须允许换行，禁止因为一个长标题撑破整行。
- 同一组元素使用统一 `gap`，不通过逐项 `margin`“凑位置”；容器变窄时整体压缩，层级关系不改变。
- 预算摘要环的图例区使用自适应网格：宽屏 3 列、窄屏 2 列、极窄屏 1 列；每个图例项不得低于 96pt 宽和 44pt 高。
- 预算分类超过 6 项时，摘要页显示前 5 项加“其他”汇总，不把文字压缩到不可读；点击“其他”进入完整分类明细。
- 圆环尺寸使用 `clamp()` 随容器变化，但不能小于 212pt；中心金额和状态在圆环内保持安全内边距。
- 页面滚动方向只有一个主轴。不能让用户在一个小卡片里同时横向、纵向滚动来寻找预算分类。

因此，新增预算后会自动重新计算列数、卡片宽度、间距和图例高度；不会通过缩小到难以阅读的文字来“硬塞”。

### 3.2 圆角

- 页面容器：28pt。
- 大卡片：22–24pt。
- 普通内容卡片：18–20pt。
- 按钮和输入框：14pt。
- 小标签和状态胶囊：10–12pt。
- 圆形图表和头像：999pt。

### 3.3 排版

| 角色 | 尺寸/行高 | 用途 |
|---|---|---|
| Display | 28/34 | 页面主标题、重要金额 |
| Title | 22/28 | 卡片标题、详情标题 |
| Headline | 17/22 | 区块标题 |

### 3.3.1 容器感知文字排版

文字不是固定像素贴在容器上，而是根据语义角色、可用宽度和内容长度共同决定尺寸：

- 页面标题、卡片标题、金额和按钮文字使用 `clamp()` 或容器查询在设计范围内流动；字号变化必须保持行高、字重和层级比例。
- 金额使用等宽数字、右对齐和可换行的金额容器；金额过长时优先增高容器，其次缩小字号，禁止覆盖、溢出或挤压相邻按钮。
- 标题使用平衡换行；核心信息允许 2 行，辅助说明最多 2 行并使用渐隐/省略；账单名称、预算名称等核心字段不能无提示截断。
- 按钮文字使用 `text-wrap: balance`，按钮高度至少 44pt；超过一行时按钮自动增高，不能把文字缩到失去可读性。
- 图表中心文字采用“最大可读字号 + 最小安全字号”策略，超过安全范围显示短格式金额，并提供完整值的辅助文本或详情入口。
- 中英文、数字、日期和长分类名都必须经过窄屏与大字号验收；不得以默认中文长度作为唯一假设。
- 对无法仅靠 CSS 稳定适配的动态数值，使用统一 `FitText`/`AdaptiveValue` 组件处理，禁止页面自行写不同的缩放算法。

统一的自适应字号范围：

| 角色 | 流动范围 | 约束 |
|---|---|---|
| 页面标题 | 24–32pt | 最多 2 行，保持标题层级 |
| 卡片标题 | 17–22pt | 允许换行，不撑破布局 |
| 重要金额 | 22–32pt | 等宽数字，超长时增高或短格式化 |
| 正文 | 15–17pt | 1.45–1.6 倍行高 |
| 辅助说明 | 12–14pt | 不低于 12pt，最多 2 行 |
| 紧凑标签 | 11–13pt | 不低于 11pt，必要时改为图标 + 短文案 |
| Body | 15/22 | 主要正文和账单内容 |
| Callout | 13/19 | 辅助说明和摘要 |
| Caption | 11/16 | 时间、来源、状态辅助信息 |
| Footnote | 10/14 | 非核心补充信息 |

金额优先使用等宽数字或系统数字字形，避免小数位跳动导致排版抖动。

### 3.4 移动端适配

- 设计基准：iPhone 430×932。
- 最小可用宽度：320pt。
- 所有底部固定元素预留 `env(safe-area-inset-bottom)`。
- 主要控件默认触控区域为 44×44pt。
- 小于 44pt 的视觉图标必须通过 padding 扩大命中区域。
- 不维护桌面端第二套页面；宽度变化只调整排列，不改变信息和交互语义。

## 4. 表面与层级

### 4.1 环境层

允许使用淡紫/淡粉的渐变、兔子氛围图和柔和光晕，但环境层不能影响正文阅读，也不能用作状态表达。

### 4.2 内容层

家庭主题、菜谱、账单、预算分类和趋势摘要使用标准内容表面：

- 较高不透明度。
- 轻描边。
- 低强度阴影。
- 不在同一内容卡片内叠加多层 blur。

### 4.3 功能层

只允许以下元素使用 Liquid Glass：

- 底部一级导航。
- 顶部浮动操作和小兔子入口。
- Bottom Sheet、确认面板和临时浮层。
- 激活态的滑块、切换和筛选控件。

功能玻璃必须有清晰的边界、对比度和按下态；不能让用户猜测哪里可以点击。

## 5. 全局组件规范

### 5.1 App Shell

- 顶部显示 Life 品牌和当前上下文。
- 小兔子 AI 入口固定在右上角，保持 44pt 命中区域。
- 内容区域纵向滚动，底部导航浮在功能层。
- 一级导航固定为：家庭空间、吃什么、财务、更多。
- HowToCook 永远是“吃什么”的子页面，不得出现在一级导航。

### 5.2 按钮

- 主要按钮：一个页面最多一个主要动作。
- 次要按钮：用于取消、查看来源、打开筛选或辅助动作。
- 危险按钮：仅用于不可逆或高风险动作，并与普通按钮分离。
- 按下时必须有缩放/亮度/背景变化等即时反馈。
- 禁用态必须同时降低可操作性和语义可用性，不能只改变透明度。

### 5.3 卡片与列表

- 整行可点击时，整行命中区域不小于 44pt。
- 右侧统一使用 chevron 表示进入详情。
- 金额、状态和时间必须有独立视觉层级。
- 列表空态必须说明原因并提供唯一主要动作。
- 长列表优先使用分组和渐进加载，不用过度阴影区分每一行。

### 5.4 Bottom Sheet

- 用于创建、筛选、AI 预览、确认和短流程操作。
- 支持下滑关闭、明确关闭按钮和系统返回。
- 键盘出现时自动上移输入区域，不能遮挡主按钮。
- 高风险确认必须显示影响范围、来源和最终动作。

### 5.5 图表和预算环

- 图表和圆环本身是交互入口，不是装饰。
- 点击先出现周期/分类摘要，再次点击进入明细；必要时提供直接“查看明细”按钮。
- 颜色之外必须有名称、金额、比例、图标或线型差异。
- 图表加载时保留尺寸，避免页面跳动。

### 5.6 小兔子 AI

- 小兔子是上下文入口，不是独立一级聊天页。
- 默认读取当前页面和当前家庭范围，不能跨家庭或跨页面无提示读取。
- AI 输出必须显示来源、生成时间、Provider/模型和适用范围。
- 任何写入都先生成 `AIActionProposal`，经过预览、权限校验、确认、执行和审计。
- AI 失败时退化为可理解的错误状态，不展示未经验证的“成功”结果。

## 6. 交互与反馈规范

### 6.1 标准手势

| 手势 | 统一含义 |
|---|---|
| 点击 | 激活、选择、进入详情 |
| 滑动 | 滚动、切换内容或返回 |
| 下拉 | 刷新当前页面数据 |
| 长按 | 仅在需要上下文操作时显示菜单 |
| 拖动 | 调整排序、时间范围或图表选择器 |

不使用自定义多指手势作为核心功能入口；任何核心动作必须有可见按钮替代方案。

### 6.2 状态反馈

- 读取：骨架屏或局部 loading，保持布局稳定。
- 写入：按钮进入进行中状态，成功后显示轻量确认。
- 网络错误：说明原因、提供重试和保留用户输入。
- 权限错误：说明“谁可以操作”，不泄露内部权限结构。
- 冲突：显示数据已变化，提供重新加载/合并路径。
- AI：区分“生成中、待确认、已执行、已拒绝、失败”。

## 7. 无障碍与系统适配

- 不能只用颜色表达状态；所有状态需要文字、图标或纹理辅助。
- 支持 Dynamic Type 思路：字号增大时允许卡片增高，禁止强行截断核心信息。
- 自适应布局必须在 320–430pt 宽度和大字号条件下保持可用：先换行/增高，再压缩间距，最后才在安全范围内缩小字号。
- 所有页面验收至少覆盖：1 项、3 项、5 项、6 项和超过 6 项预算分类；覆盖短标题、长标题、长金额和中英文混排。
- 支持降低透明度：功能玻璃退化为不透明浅色表面，层级和操作不改变。
- 支持降低动态效果：取消漂浮、缩放和渐变动画，保留状态切换。
- 所有图标按钮必须有可读的 `aria-label`。
- 文字和关键图形需要达到可读对比度，不能以“玻璃效果”牺牲可读性。

## 8. 总体 UI 验收闸门

总体设计系统在进入页面垂直切片前必须满足：

- [ ] 所有页面只能使用本文件定义的颜色、间距、圆角、层级和状态。
- [ ] Liquid Glass 只出现在功能层，内容层保持稳定可读。
- [ ] 四项一级导航和 HowToCook 二级关系固定。
- [ ] 小兔子 AI 入口、来源、提案和确认行为统一。
- [ ] 预算环、趋势图、账单列表等数据展示都有统一点击反馈和下钻语义。
- [ ] 加载、空态、错误、权限、冲突和 AI 状态已有公共实现方案。
- [ ] 44pt 命中区域、返回、键盘、下拉刷新和减少动效行为可验收。
- [ ] 低透明度、大字号和窄屏条件下页面仍可用。
- [ ] 新增预算分类后会自动换列、调整宽度和高度，且不会出现重叠、溢出或小于 44pt 的命中区域。
- [ ] 图表、圆环、按钮和容器内文字均通过容器感知字号/换行规则处理，不依赖固定字号硬塞。
- [ ] 320–430pt、1/3/5/6/>6 项数据以及长金额场景均完成视觉验收。
