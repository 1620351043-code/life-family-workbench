# Life 家庭生活工作台

## 移动端信息架构与核心用户流程 v0.1

> 状态：UI 重做前的结构基线。
>
> 依据：[PRD v0.10](./Life-家庭生活工作台-PRD-v0.10.md) 和 [技术路线评审 v0.1](./Life-家庭生活工作台-技术路线评审-v0.1.md)。本文件不规定颜色、字体、玻璃拟态、兔子形象或具体视觉风格。

## 1. 信息架构原则

### 1.1 一级导航只服务四件事

移动端固定四个一级入口：

1. **家庭空间**：围绕主题发布、讨论和达成共识。
2. **吃什么**：先推荐，再选择，再进入 HowToCook 和采购清单。
3. **财务**：从家庭财务总览进入账单、预算、趋势、资产和导入。
4. **更多**：家庭与成员、AI 设置与数据授权、个人设置、系统说明。

HowToCook 是“吃什么”的子能力，不进入一级导航；家庭空间不包含独立收件箱、通知中心或私聊。

### 1.2 页面由任务和状态决定

每个页面必须回答四个问题：

- 用户此刻要完成什么任务？
- 页面展示的数据来自哪个领域对象？
- 点击每一个摘要、图表、列表项后进入什么明细？
- 当前用户无权、无数据、处理中或失败时看到什么？

视觉稿可以改变页面表现形式，但不能删除下钻、权限、撤销、来源和状态。

### 1.3 首页不承担所有功能

四个一级首页只展示高频任务的摘要和入口。低频设置、授权、审计和导入过程进入专门页面，避免首页被大量卡片稀释。

## 4. 首页信息设计

### 4.1 家庭空间首页

内容顺序：

1. 当前家庭名称和成员入口。
2. “发布一个主题”主入口。
3. 主题筛选：全部、想法、需求、灵感、待处理。
4. 主题列表：标题、类型、状态、最后讨论时间、评论数、关联内容。
5. 家庭 AI 摘要入口：只显示基于当前主题的摘要状态，不展示全局聊天。

空态：解释主题是家庭协作的核心，并提供一个明确的发布按钮。无权限态：说明当前主题对该成员不可见，不泄露标题或摘要。

### 4.2 吃什么首页

内容顺序：

1. 当前餐次、时间和家庭上下文。
2. 推荐卡：菜名、预计耗时、适合人数、主要食材、推荐理由和来源。
3. “智能搭配一餐”入口。
4. “搜索菜谱”入口。
5. 最近自动采集的吃过什么记录。
6. 采购清单入口和未完成数量。

推荐卡默认进入选择态，不直接跳过确认进入菜谱详情。搜索结果选择后仍进入同一个确认/详情链路。

### 4.3 财务首页

内容顺序：

1. 当前周期切换和数据新鲜度。
2. 净资产、账户余额、收入、支出、净现金流摘要。
3. 预算多环整体图和分类图例。
4. 收入/支出/净现金流趋势线。
5. 实物资产累计现金成本趋势入口。
6. 待处理导入、关联、确认和异常。
7. 最近流水。

每个区域必须同时提供：数值、周期、来源/更新时间、点击下钻行为和空态。图表不能只提供图片或不可点击的装饰。

### 4.4 更多

更多不承担日常任务，只放低频配置：

- 家庭所有者管理成员和儿童财务/AI 权限。
- 每家庭独立 AI API 连接、测试、轮换、禁用和记忆清除。
- 推荐开关和自动偏好清除。
- 登录安全、数据导出、原始账单保留 365 天说明。

## 5. 核心用户流程

### 5.1 新用户与家庭归属

```text
注册/登录
  ├─ 未归属家庭 → 创建家庭 或 输入邀请码
  │                    ↓
  │              创建唯一家庭成员关系
  └─ 已归属家庭 → 直接进入该家庭

已归属家庭用户再次创建/加入家庭
  → 明确拒绝
  → 引导原家庭退出/账号迁移流程
  → 保留审计
```

页面必须在首次进入时说明：一个账号只能属于一个家庭。不能把家庭切换器设计成普通下拉框。

### 5.2 家庭主题协作

```text
家庭空间首页
  → 发布主题
  → 选择：想法 / 需求 / 灵感
  → 填写标题和正文
  → 发布
  → 家人评论 / 一层回复
  → 需求状态变化
  → AI 生成摘要、共识、未决事项和建议草稿
  → 用户查看原始评论
  → 用户确认或忽略建议
```

关键交互：AI 摘要必须能展开原始评论来源；AI 不直接把“建议”写成已确认状态；主题归档后只读，不再接受新讨论。

### 5.3 吃什么 → HowToCook → 采购清单

```text
吃什么首页
  → 推荐卡
  → 选择一个或多个菜谱
  → 推荐选择确认
      ├─ 修改份数
      ├─ 查看冲突/重复食材
      └─ 确认
  → HowToCook 菜谱详情
      ├─ 查看食材 / 工具 / 步骤
      ├─ 开始烹饪
      ├─ 份数换算
      └─ 生成/更新采购清单
  → 高置信完成事件
  → 自动记录吃过什么
  → 更新家庭长期推荐特征
```

规则：浏览和收藏不直接生成“吃过什么”；吃过什么页面不能新增、编辑、评分或补录。AI 的份数换算和替代建议需要显示“AI 建议”，食品安全内容回到审核后的 HowToCook 内容。

### 5.4 搜索菜谱

```text
吃什么首页
  → 搜索菜谱
  → 输入菜名/食材/口味/时间/难度
  → 结果列表
  → 选择菜谱
  → 推荐选择确认
  → HowToCook 详情
```

搜索无结果时只能给出放宽筛选、检查输入或回到推荐的建议，不生成不存在的菜谱。

### 5.5 财务首页下钻

```text
财务首页
  ├─ 点击净资产/收入/支出/净现金流卡
  │    → 对应周期的账本过滤结果
  ├─ 点击预算环 / 图例 / 环心
  │    → 分类账单 / 当前周期总账单
  ├─ 点击收入/支出趋势数据点
  │    → 对应日期或周期账单
  ├─ 点击实物资产成本数据点
  │    → 对应资产事件和关联账单
  └─ 点击最近流水
       → 交易详情
```

所有下钻统一携带 `drilldown_ref`，而不是让前端依据展示名称重新猜查询条件。返回列表顶部展示“来自：预算/趋势/资产/摘要”的来源提示，用户可以清除过滤回到全部流水。

### 5.6 多来源账单导入

```text
财务首页
  → 导入账单
  → 选择来源或自动识别
  → 上传文件
  → 识别编码 / Sheet / PDF / ZIP
  → 扫描前 100 行并提示表头行
  → 用户确认表头和字段映射
  → 标准化预览
  → 错误行修正
  → 生成重复/关联候选
  → 导入关联审核
  → 用户确认关系
  → 写入正式账本
  → 查看导入结果和可下钻统计
```

中途退出必须支持恢复导入批次；取消、失败、撤销和成功状态不可混淆。正式账本写入前，用户必须看到将被新增、合并、忽略和待确认的数量。

### 5.7 家庭所有者授权儿童财务

```text
更多 → 家庭与成员
  → 选择儿童成员
  → 财务授权
  → 选择资源范围：账户 / 分类 / 周期 / 汇总或明细
  → 设置有效期和操作范围
  → 确认授权
  → 记录审计
```

默认不授权财务。授权撤回应立即影响后续读取；已加载页面在下一次敏感请求时重新校验，不依赖客户端缓存继续展示。

### 5.8 家庭 AI 连接与记忆

```text
更多 → AI 设置与数据授权
  → 配置 Endpoint / 协议 / 模型 / API 密钥
  → 服务端写入密钥引用
  → 测试连接
  → 选择允许的能力和数据范围
  → 开启家庭 AI
  → 主题/吃什么/财务页面出现上下文 AI

清除记忆
  → 二次确认
  → 结构化记忆 / 文件 / 向量 / 缓存 / 任务进入清理
  → 展示清理状态和审计结果
```

没有家庭 AI 连接时，页面仍可使用规则推荐和确定性财务能力；不能显示“正在使用默认 AI”。

## 6. 财务交互契约

### 6.1 图表数据契约

财务 API 为每个展示元素返回：

```json
{
  "label": "餐饮",
  "value": 1999.00,
  "period": "2026-08",
  "color_token": "category.food",
  "drilldown_ref": {
    "type": "ledger_filter",
    "filter_id": "fd_..."
  },
  "source_count": 12,
  "updated_at": "2026-08-23T10:00:00+08:00"
}
```

前端只使用 `drilldown_ref` 调用明细接口；不根据颜色、标题或金额拼接 SQL 条件。

### 6.2 预算多环

- 环心：总预算、总已用、整体进度，点击进入当前周期所有支出。
- 单环：分类、已用、额度、剩余/超支，点击进入分类账单。
- 图例：与单环使用相同的点击行为。
- 超支：颜色之外增加文字、图标和数值，不依赖颜色识别。
- 无预算分类：显示“未纳入预算”并可下钻到对应账单。

### 6.3 收入/支出趋势

- 支持日、周、月、季度和自定义范围。
- 图例可隐藏/显示线条，但不会改变统计接口的原始数据。
- 数据点点击进入该点对应的日期/周期。
- 无数据、数据不足、导入处理中和统计失败必须分别展示。

### 6.4 实物资产成本趋势

- 可切换购买成本、维护成本、总成本和净现金成本。
- 数据点点击进入资产事件。
- 资产事件可以反向进入关联账单。
- 资产被转让、出售或处置后，历史成本不被重写，只增加事件。

## 7. 页面状态矩阵

| 状态 | 页面通用表现 | 允许动作 |
|---|---|---|
| 首次使用 | 说明页面任务，给一个主动作 | 创建、导入、发布或开始推荐 |
| 加载中 | 保留页面骨架，不显示旧家庭数据 | 取消可取消任务 |
| 空数据 | 说明为什么为空，不伪造数字 | 创建、导入或返回推荐 |
| 处理中 | 显示任务状态、更新时间和预计下一步 | 后台运行、退出、重试 |
| 成功 | 显示结果数量、来源和下一步 | 查看详情、继续任务 |
| 失败 | 显示稳定错误码/可读原因 | 重试、修正、放弃 |
| 网络断开 | 保留已确认的本地非敏感状态 | 重试，不写入敏感缓存 |
| 无权限 | 只说明无权，不泄露资源内容 | 返回、请求授权 |
| 资源删除 | 说明资源不可用 | 返回上级 |
| 可撤销 | 显示影响范围和撤销入口 | 撤销、查看审计 |
| 权限变化 | 下次请求重新校验并清除敏感展示 | 返回、重新加载 |

## 8. UI 设计前的组件边界

UI 设计系统至少需要定义以下语义组件，而不是只定义视觉卡片：

- `HouseholdScopeHeader`：当前家庭、成员关系和敏感状态提示。
- `TopicCard`、`CommentThread`、`TopicStatusControl`。
- `RecommendationCard`、`RecipeSelectionTray`、`RecipeSourceBadge`。
- `RecipeIngredientList`、`RecipeStepList`、`ShoppingListItem`。
- `FinanceSummaryCard`、`BudgetRingChart`、`TrendChart`、`AssetCostChart`。
- `DrilldownBanner`：显示明细来自哪个摘要或图表。
- `ImportStepper`、`HeaderDetectionPreview`、`FieldMappingTable`、`ReconcileCandidateCard`。
- `PermissionScopeEditor`、`AIConnectionForm`、`MemoryClearStatus`。
- `EmptyState`、`PermissionState`、`TaskProgress`、`ErrorRetry`、`UndoToast`。

每个组件都要有：加载、空、错误、无权限、处理中、成功和触摸操作反馈。不要先抽象“万能卡片”，再把不同领域的行为塞进同一个组件。

## 9. UI 重做的交付顺序

1. 先画移动端用户流程和状态图。
2. 再画页面低保真结构，验证信息层级和下钻。
3. 再建立财务图表、导入映射和权限授权的交互原型。
4. 再建立颜色、字体、插图、动效和组件视觉系统。
5. 最后为 390px、430px 和弱网场景做高保真设计与标注。

首轮 UI 原型必须覆盖：

- 家庭空间：主题首页、主题详情、评论和 AI 摘要。
- 吃什么：推荐、选择确认、HowToCook 详情和采购清单。
- 财务：财务首页、预算环下钻、趋势下钻、资产成本下钻和导入映射。
- 更多：儿童财务授权和家庭 AI 连接/记忆清除。

## 10. UI 验收闸门

设计稿在进入前端开发前，必须证明：

- 用户不看旧稿也能理解四个一级入口的关系。
