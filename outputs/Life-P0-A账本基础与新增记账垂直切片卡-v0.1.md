## 3. 账本数据规则

- `ledger_transaction` 是用户看到的一笔交易。
- `ledger_entry` 是账户余额变化分录；`debit` 增加账户余额，`credit` 减少账户余额。
- 收入：目标账户一条 `debit` 分录。
- 支出：来源账户一条 `credit` 分录。
- 转账：转出账户一条 `credit`、转入账户一条 `debit`，金额相等。
- 撤销：交易状态变为 `voided`，余额查询排除该交易，原交易和审计记录保留。
- 编辑：仅允许手动来源交易；更新交易和分录必须在同一事务中完成，并写入前后摘要。
- 导入来源无法可靠映射到账户时，交易可以进入统一账本但不能假装已完成账户余额；必须显示待处理状态并阻止错误余额统计。

## 4. 移动端 UI/UX 规范

- 财务首页增加“新增记账”主入口，与“导入账单”并列但视觉上区分手动和文件导入。
- 新增记账使用 Bottom Sheet，不离开财务上下文；顶部显示当前家庭范围和小兔子 AI 入口。
- 使用分段控件切换“支出 / 收入 / 转账”，切换后动态调整字段，避免把三种表单全部堆在一页。
- 金额输入优先级最高；键盘打开时金额和底部保存按钮不被遮挡。
- 转账显示“转出账户 → 转入账户”和预计余额变化；禁止选择相同账户。
- 保存前显示“本次余额变化”预览；保存中按钮进入进行中状态，成功后返回账本并显示轻量确认。
- 金额、账户、分类、时间和保存按钮命中区不小于 44pt；长分类名使用自适应换行。
- 失败时保留用户已填写内容；权限不足时说明需要家庭所有者授权，不泄露其它家庭信息。
- 交易详情提供“编辑”和“撤销”入口；撤销为二次确认 Sheet，显示影响账户、金额和预算。
- 遵循淡粉淡紫内容层 + 功能层 Liquid Glass；不在内容卡片中叠加多层 blur。

## 5. 初步 API 契约

| 方法 | 路径 | 目的 |
|---|---|---|
| `GET` | `/api/finance/accounts` | 获取当前家庭账户及计算余额 |
| `POST` | `/api/finance/accounts` | 创建账户和期初余额 |
| `GET` | `/api/finance/categories` | 获取当前家庭可用分类 |
| `POST` | `/api/finance/transactions` | 创建手动收入/支出/转账 |
| `GET` | `/api/finance/transactions` | 获取可筛选账本列表 |
| `PATCH` | `/api/finance/transactions/{transactionId}` | 编辑手动交易 |
| `POST` | `/api/finance/transactions/{transactionId}/void` | 撤销手动交易 |

所有写接口必须从服务端会话推导 `household_id`，客户端不能覆盖家庭范围；错误返回必须带可追踪错误码。
