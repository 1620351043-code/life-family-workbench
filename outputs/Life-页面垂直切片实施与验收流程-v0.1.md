# Life 页面垂直切片实施与验收流程 v0.1

更新时间：2026-08-24

## 一、基本原则

每一个页面都是一个可独立交付、可独立验收、可追踪回归的垂直切片。一个页面不能只完成视觉稿，也不能只完成接口或组件；必须从用户入口一直打通到真实数据、真实交互和异常反馈。

页面完成的定义是：

> 用户可以在移动端真实打开页面，完成该页面定义的核心任务；页面的数据来自正确的家庭租户和 API 契约；关键操作有即时反馈、错误恢复、权限保护和可回归测试。

## 二、单页面标准流程

### Step -1：总体 UI 设计系统闸门

在任何页面垂直切片开始前，先完成 `outputs/Life-移动端总体UI设计系统-v0.1.md` 的收口。它统一颜色角色、内容层与功能玻璃层、间距、圆角、排版、触控目标、导航、AI 入口、状态反馈和无障碍降级规则，并统一自适应容器、多数据项重排、容器感知字号和长内容处理规则。

页面设计只能在该系统中选择和组合组件；如果某个页面确实需要新增模式，必须先补充总体设计系统并通过视觉/交互审查，再进入页面开发。

任何新增多容器页面必须补充 320–430pt、1/3/5/6/>6 项数据和长金额验收；禁止通过固定宽度、绝对定位或页面私有的字号缩放算法解决排版问题。

### Step 0：页面立项

先建立页面切片卡，不直接写代码。

页面切片卡至少包含：

- 页面 ID、名称、一级入口、路由和返回路径。
- 页面解决的唯一核心任务。
- 页面不负责的事情，以及会跳转到哪个页面。
- 进入条件、家庭成员权限和数据隔离边界。
- 成功、空数据、加载中、失败、无权限、过期和重复操作状态。
- 依赖的 API、数据库实体、AI Provider 或 HowToCook 数据来源。
- 可量化验收标准。

### Step 1：产品与信息架构审查

产品经理确认：

- 页面是否真的需要独立存在，能否合并到上一级页面。
- 页面核心任务是否只有一个主路径。
- 用户从哪里进入，完成后回哪里。
- 页面是否产生新数据、修改旧数据或触发 AI 写入。
- 页面是否与 PRD、页面树、权限模型和跨页面数据关系一致。

输出物：页面目标、任务流、状态清单、边界清单。

### Step 2：低保真与交互规范

设计师和前端交互工程师共同定义：

- 页面结构、信息层级、主按钮和次按钮。
- iOS HIG 手势、返回、下拉刷新、滑动、长按、底部 Sheet 和键盘行为。
- 44pt 最小触控目标、焦点态、禁用态、加载态、成功反馈和错误反馈。
- Liquid Glass 容器、颜色、圆角、阴影、模糊层级和动态背景。
- 小兔子 AI 的入口位置、上下文、来源展示和行动提案状态。

输出物：低保真页面、交互说明、页面状态图和动效/反馈说明。

### Step 3：数据与 API 契约

在页面代码前完成：

- OpenAPI 路径、请求、响应和错误码。
- 数据库迁移、索引、复合外键和 RLS 策略。
- 所有金额、时间、来源 ID 和 `drilldown_ref` 的格式。
- 页面数据与家庭 ID 的绑定方式，禁止客户端提交家庭 ID 改变租户。
- 写操作的幂等键、版本号、权限校验和审计动作。
- AI 结果的 Provider、模型、来源引用、置信范围和提案状态。

输出物：OpenAPI 变更、数据库迁移、契约测试和数据样例。

### Step 4：页面实现

按照从外到内的顺序实现：

1. 页面路由和返回行为。
2. 页面骨架和设计令牌。
3. 加载、空态、错误态、无权限态和过期态。
4. 真实 API 请求层和状态管理。
5. 主任务成功路径。
6. 次级交互和跨页面跳转。
7. AI 入口、来源、提案确认和审计反馈。

页面不允许用静态 fixture 伪装真实成功状态。开发 fixture 只能显式标注为设计数据或测试数据。

### Step 5：自动化测试

每个页面至少包含：

- API 契约测试。
- 租户隔离测试：当前家庭可见，其他家庭不可见。
- 权限测试：owner、adult、child、guest 的允许和拒绝路径。
- 核心成功路径测试。
- 重复点击、重复提交、版本冲突和幂等测试。
- 加载失败、空数据和异常响应测试。
- 如果页面涉及 AI，必须测试来源引用、提案确认/拒绝和审计记录。

### Step 6：真实移动端浏览器验收

自动化测试通过后，使用真实运行页面验收：

- 移动端宽度和安全区布局。
- 页面首屏信息是否正确，是否出现假数据或乱码。
- 每个主按钮、返回、表单、输入框、键盘和手势是否可用。
- 页面状态切换是否即时且可理解。
- 关键数据点击后是否进入正确的详情或下钻页面。
- AI 操作是否明确显示来源、权限和确认结果。

浏览器验收必须记录：页面 URL、测试时间、测试账号/家庭范围、操作步骤、预期结果、实际结果和截图/DOM 证据。

### Step 7：问题修复与回归

所有问题按以下优先级处理：

- P0：数据串租户、账本重复记账、越权写入、不可恢复数据错误。
- P1：核心任务无法完成、主按钮失效、错误数据、关键页面无法打开。
- P2：局部交互不一致、视觉错位、文案和反馈问题。
- P3：非核心优化和动效细节。

页面只有 P0/P1 清零、P2 有明确处理计划后，才可标记为可交付。

### Step 8：页面交付记录

每个页面交付时必须记录：

- 页面切片卡和最终路由。
- 关联 PRD、OpenAPI、迁移和代码文件。
- 测试命令及结果。
- 浏览器验收结果和未解决问题。
- 权限与租户隔离结论。
- 下一页面的依赖和明确不包含项。

## 三、页面 Definition of Ready

页面只有满足以下条件才能开始开发：

- 核心用户任务已确定。
- 页面边界和不包含项已确定。
- 页面状态清单已完成。
- UI 低保真和交互规范已确认。
- 容器自适应规则已确认，包含窄屏、大字号、长标题、长金额和多数据项重排。
- API 和数据库边界已审查。
- 权限和租户隔离规则已明确。
- 验收标准可被自动化或浏览器操作验证。

## 四、页面 Definition of Done

页面只有满足以下条件才能关闭切片：

- 路由、返回和跨页面入口可用。
- 主成功路径和所有必要状态已实现。
- 使用真实 API 和正确租户上下文。
- OpenAPI、迁移、RLS 和代码保持一致。
- 自动化测试通过。
- 移动端浏览器验收通过。
- 320–430pt 及大字号视觉验收通过，容器无重叠、溢出或不可读压缩。
- P0/P1 问题为零。
- 页面交付记录已写入项目文档。

## 五、Life 页面执行顺序

按依赖和风险排序，不按视觉稿出现顺序排序：

1. 家庭空间首页。
2. 家庭主题详情、发布和评论。
3. 小兔子 AI 主题摘要与行动提案。
4. 财务首页。
5. 财务预算下钻。
6. 财务收入/支出趋势下钻。
7. 财务实物资产成本趋势下钻。
8. 财务账单导入、表头识别和字段映射。
9. 财务多来源关联审核与统一账本详情。
10. 吃什么推荐。
11. 吃什么搜索与自动历史。
12. HowToCook 菜谱详情。
13. 采购清单与导出。
14. 更多中的家庭成员、儿童财务授权和 AI 设置。

每完成一个页面，先完成本流程的 Definition of Done，再进入下一个页面。
