# Life 财务 UI/UX 差距修订版 v0.2

更新时间：2026-08-25  
负责人：移动端 UI/UX 与前端交互联合审查  
状态：设计修订基线，待按本版实施并重新验收  
范围：仅移动端，不建设桌面端第二套财务界面

> 本文不是新增业务 PRD，而是把当前财务垂直切片、PRD、移动端 UI 设计系统与真实运行态审查结果，收敛成一份可直接指导设计、开发和验收的 UI/UX 差距修订版。它优先解决“用户看不懂、点不进去、状态不可信、窄屏不美观”四类问题。

## 0. 结论先行

当前财务模块的业务垂直切片已经具备较完整的真实数据、账本、导入、关联、资产、权限和财务 AI 基础；`npm run api:typecheck`、`npm run web:typecheck`、`npm run web:build`、OpenAPI 校验、迁移烟测和 PostgreSQL 垂直测试已经通过。

但 UI/UX 尚未达到“可以收口”的标准，主要差距集中在：

1. 财务首页头部承载过多按钮，430pt 下标题与操作区会发生真实布局冲突；
2. 摘要卡、预算环、趋势图、资产点和明细的“可点击即下钻”契约还不够一致；
3. 多环预算还缺少明确的余额/缺口表达、超预算语义和无预算引导；
4. 图表仍偏展示型，缺少零轴、金额刻度、点级提示和完整可达的资产事件；
5. Bottom Sheet 缺少统一的 dialog 语义、焦点管理、Escape/系统返回和下滑关闭；
6. 错误、无权限、过期、冲突、空态与处理中状态没有形成统一语言；
7. 导入向导虽已具备“表头行号 + 数据内容预览”，但仍缺少可恢复流程、错误报告、候选原因和提交后结果下钻；
8. 长金额、品牌兔子、屏幕阅读器语义和权限可见性仍有实现差距。

**发布判定：**当前业务切片“开发闭环通过”；当前财务 UI/UX“未通过统一收口”，必须完成本文件中 P0/P1 项后再进行最终视觉验收。

本版只写入设计与验收文档，不直接修改业务代码。

## 1. 设计目标与审美方向

### 1.1 一句话设计目标

让家庭成员在柔和的淡粉与淡紫氛围中，快速看懂“钱从哪里来、花到哪里去、预算还剩多少、每一条数字能否追溯”，并且在任何宽度、状态或权限下都保持安静、清楚、可信。

### 1.2 视觉关键词

```text
温柔：淡粉、淡紫、柔和光晕，降低财务工具的压迫感
克制：内容层稳定不透明，玻璃只用于功能层，不让装饰抢走数据
可信：金额、周期、来源、状态和错误都明确，不用颜色单独表达含义
秩序：严格的间距、层级、网格、点击反馈和页面转场
亲和：小兔子是上下文助手入口，不是干扰阅读的常驻聊天气泡
```

### 1.3 审美边界

- 不把所有容器都做成模糊玻璃；账单、金额、表单和图表使用稳定的内容表面。
- 不用大面积紫色渐变承载小字号文字；渐变只做环境层、AI 入口或轻量强调。
- 不用阴影堆叠制造层次；优先用留白、表面明度和分组关系制造秩序。
- 不让“顶级审美”变成信息隐藏。财务页首先要可靠、可操作，其次才是氛围感。
- 不用静态装饰图表冒充交互；凡是展示金额、比例、分类或趋势的图形，必须有可达的下钻入口。

## 3. 财务信息架构与页面层级

### 3.1 一级导航

```text
家庭空间     吃什么     财务     更多
```

财务是一级入口，但财务内部不再增加底部导航项。所有财务子功能通过页面栈、工具菜单或上下文 Sheet 进入。

### 3.2 财务页面树

```text
财务首页
├─ 周期选择 / 自定义周期
├─ 账单明细（全部流水）
│  └─ 统一账单详情
├─ 新增记账（短表单 Sheet；复杂编辑升级为全屏页面）
├─ 账户、分类与预算管理
│  ├─ 账户列表 → 账户详情 / 余额变动
│  ├─ 分类列表 → 分类详情 / 规则
│  └─ 预算列表 → 预算详情 / 周期与分类
├─ 实物资产
│  ├─ 资产列表 → 资产详情
│  └─ 资产事件 → 事件详情 / 关联账单
├─ 导入账单
│  ├─ 文件与批次
│  ├─ 表头与字段映射
│  ├─ 关联候选审核
│  └─ 提交结果 / 错误报告
├─ 财务 AI 解读
│  ├─ 只读摘要
│  ├─ 来源账单
│  └─ AIActionProposal 预览与确认
├─ 成员财务权限与审计
└─ 导出任务 / 下载状态
```

### 3.3 页面与 Sheet 的选择规则

| 场景 | 载体 | 原因 |
|---|---|---|
| 新增一笔简单收入/支出 | 中高位 Sheet | 保持当前页上下文，完成后回到财务首页 |
| 转账、编辑复杂分录、拆分账单 | 全屏子页面 | 字段多、需要预览余额和完整错误说明 |
| 周期、图例、短筛选 | Sheet 或内嵌卡片 | 选择后立即刷新当前视图 |
| 全部流水、账户、资产、导入批次 | 全屏子页面 | 需要长列表、滚动、搜索、分页和系统返回 |
| 关联审核、权限编辑、AI 提案 | 全屏流程页或大 Sheet | 需要显示影响范围、来源、审计与最终确认 |
| 危险操作确认 | 统一确认 Sheet | 不使用浏览器原生 `confirm`，保证品牌与可访问性一致 |

## 4. 视觉设计系统修订版

### 4.1 色彩角色

沿用总体 UI 系统 Token，不允许财务页面自行创造近似色。

| 角色 | Token | 建议值 | 财务用途 |
|---|---|---:|---|
| 页面底色 | `--life-bg-base` | `#F7F2FB` | 稳定背景 |
| 淡紫氛围 | `--life-bg-lavender` | `#DCD8FF` | 环境层 |
| 淡粉氛围 | `--life-bg-blush` | `#FFE1E2` | 环境层 |
| 主文字 | `--life-text-primary` | `#252642` | 标题、金额、事实 |
| 次文字 | `--life-text-secondary` | `#686D8C` | 解释和辅助信息 |
| 主操作 | `--life-accent` | `#5B72F4` | 主要按钮、选中态、链接 |
| 收入/成功 | `--life-success` | `#2D9B72` | 收入、完成、正常 |
| 支出/警告 | `--life-warning` | `#C88628` | 接近预算、待确认 |
| 危险/超支 | `--life-danger` | `#C94D69` | 超预算、失败、撤销 |
| 财务模块色 | `--life-finance-green` | `#2DAD78` | 财务身份，不替代状态色 |
| 内容表面 | `--life-surface-content` | `rgba(255,255,255,.78)` | 账单、图表、表单 |
| 功能玻璃 | `--life-material-functional` | `rgba(255,255,255,.58)` | 导航、Sheet、浮动控件 |

颜色不是唯一语义：收入/支出/超预算必须同时有文字、图标、正负号、纹理或线型差异。

### 4.2 预算环视觉规则

一个预算容器只呈现一个整体圆：

- 外圈到内圈分别对应分类；每个环使用固定颜色，不因数据排序随机变化。
- 已用部分使用实色弧段；剩余部分使用同色低明度轨道；超预算时实色弧段保留并向外增加危险缺口标记，不简单截断成 100%。
- 中心显示三层信息：`本周期预算`、`已用金额`、`剩余 ¥X / 超出 ¥X`。百分比作为次级信息，不抢金额层级。
- 每一环必须有独立的 44pt 命中目标；图例按钮是同一数据入口的第二命中目标。
- 预算 0 条：显示浅色空环 + “还没有预算” + “创建预算”唯一主动作。
- 预算 1/3/5/6/7+ 条：分别验证 1 列、2 列、3 列和“前 5 项 + 其他”布局。
- “其他”必须有服务端生成的分类级 `drilldown_ref`，不能复用预算中心总入口。

### 4.3 图表视觉规则

- 收入、支出、净现金流至少各自有明确图例和线型；净现金流必须绘制零轴，正值和负值在零轴上下可读。
- 图表保留坐标容器和日期刻度；无数据时保留图表轮廓，显示“当前周期暂无数据”和下一步入口。
- 触摸点可命中，命中后显示 tooltip：日期/周期、金额、系列名、进入明细按钮。
- 不用采样隐藏用户可查证的点；当点过多时视觉上降噪，但触摸轨道仍覆盖完整数据区间。
- 资产趋势区分总成本、净现金、购买、维护、回收；每个切换项仍可进入对应资产事件列表。
- 图表标题右侧提供“全部明细”文字按钮，避免用户必须精准点到曲线。

### 4.4 间距、圆角与动态排版

- 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32pt`。
- 页面水平内边距：16pt；区块间距：24pt；卡片内边距：16–20pt；列表行间距：8–12pt。
- 页面容器圆角 28pt；大卡片 22–24pt；普通卡片 18–20pt；输入和按钮 14pt；状态胶囊 10–12pt。
- 触控区域默认不小于 44×44pt；视觉图标小于 44pt 时用 padding 扩大命中区。
- 预算图例使用容器自适应网格：宽屏 3 列、常规窄屏 2 列、极窄屏 1 列；单项至少 96pt 宽、44pt 高。
- 卡片统一使用 `min-width: 0`、统一 `gap` 和自动换列，禁止用逐项 margin 硬凑位置。
- 文字根据容器和语义流动，不以缩小到不可读为代价塞入固定高度。
- 金额使用等宽数字；超长时优先短格式化并提供完整值，再增高容器，禁止静默裁剪。
- 标题最多两行；核心账单名称、预算名称和金额不能无提示截断。
- 兔子头像、品牌标记改为受控本地资产/组件，不使用不同操作系统会变化的 emoji。

### 4.5 动效与反馈

- 点击：立即有亮度/背景/轻微缩放反馈；按钮不能静默无响应。
- Sheet：上滑出现、下滑关闭；存在明确关闭按钮；系统返回与手势关闭语义一致。
- 数据刷新：保留旧内容尺寸，显示局部 loading，不让整页跳动。
- 成功：短时 toast/状态条 + 内容局部刷新；不可只依赖颜色。
- 失败：保留用户输入和筛选上下文，提供“重试”与“查看详情”。
- 减少动态效果时，取消 shimmer 和复杂位移动画，但保留状态、层级和操作反馈。

## 5. 全局交互 UX 规范

### 5.1 财务首页首屏顺序

首屏从上到下只保留一条清晰的决策路径：

```text
页面标题 + 周期
→ 一个主动作：新增记账
→ 摘要卡：净资产 / 账户余额 / 收入 / 支出 / 净现金流
→ 多预算整体圆环
→ 收支趋势
→ 实物资产成本趋势
→ 最近流水与 AI 解读
```

“账户与预算、资产、导入、导出、权限”全部收进财务工具入口或对应子页面，避免和主动作争夺头部空间。

### 5.2 统一下钻规则

所有“展示数字”和图形入口都必须满足同一个闭环：

```text
点击 → 立即显示选中反馈 → 打开对应筛选结果 → 显示当前筛选条件
→ 点击任意流水 → 统一账单详情 → 查看来源记录/关联关系 → 返回保留原筛选
```

下钻优先使用服务端生成的 `drilldown_ref`。前端不能根据文字自行拼接家庭范围或账单条件。

最低下钻覆盖：

- 五张摘要卡：分别进入净资产、账户余额、收入、支出、净现金流结果；
- 预算中心、每一个预算环和“其他”分类；
- 趋势每个周期点及图表“全部明细”；
- 每一个资产成本点和资产事件；
- 最近流水、“全部流水”；
- 导入提交摘要的“已入账 / 待审核 / 重复 / 失败”四类结果。

### 5.3 Bottom Sheet 行为合同

所有 Sheet 使用同一组件合同：

- 容器语义：`role="dialog"`、`aria-modal="true"`、标题通过 `aria-labelledby` 关联。
- 打开后焦点进入标题或第一个可操作控件；关闭后焦点回到原始触发按钮。
- 支持明确关闭按钮、下滑关闭、系统返回和 Escape；不可只依赖某一种手势。
- Sheet 内有滚动时，滚动区域与拖拽区域分离，避免用户滚动表单时误关闭。
- 键盘出现时，主按钮必须保持可见或可滚动到；表单错误定位到第一个错误字段。
- 高风险操作使用品牌确认 Sheet，不使用原生 `window.confirm`。

### 5.4 权限与安全反馈

- 进入财务页面先展示当前家庭、当前操作者和可用权限；无权限时不渲染可执行按钮。
- 儿童成员默认为拒绝；所有者修改儿童权限时显示“影响成员、权限范围、立即生效时间”。
- 权限变化、过期、撤销、冲突均显示原因和下一步，不泄露其他家庭数据。
- 所有写入、确认、撤销和权限修改都显示审计可追溯提示。

## 6. 页面级修订方案

### 6.1 财务首页

**目标：**一眼看懂，继续查证，不把所有工具都堆在标题栏。

布局：

1. 顶部只显示标题、周期、小兔子 AI 入口和“新增记账”主按钮；
2. “财务工具”打开工具 Sheet，包含账户预算、资产、导入、导出、权限与审计；
3. 摘要卡最多三列，窄屏自动两列/一列；净资产和账户余额必须可以进入对应明细；
4. 预算环作为视觉锚点，中心明确剩余预算；环段和图例双入口；
5. 趋势图采用稳定内容卡，图表点击显示 tooltip，标题提供全部明细；
6. 最近流水卡最后一行固定显示“查看全部流水”；
7. AI 入口放在资产趋势之后，明确“只读解释、来源可追溯、不会自动改账”。

状态：首次加载、刷新中、真实数据、无预算、无流水、无趋势、网络失败、下钻过期、无权限、周期无效均按第 8 节矩阵实现。

### 6.2 收支明细与统一账单详情

- 顶部显示返回、当前筛选条件、搜索和筛选按钮；筛选条件使用胶囊，可一键清除。
- 列表按日期分组，收入/支出/转账同时显示方向、账户、分类、金额和来源标记。
- 每行 60pt 以上，整行可点击；右侧 chevron；支持继续加载和空态。
- 详情页明确：统一账单、分录、账户、分类、来源记录、重复/父子/退款/手续费/拆分关系、创建人、创建时间、审计。
- 编辑、撤销、拆分等动作根据权限显示；撤销必须显示影响预算和余额的范围。

### 6.3 新增记账

最短路径：

```text
新增记账 → 收入/支出/转账 → 金额 → 账户 → 分类 → 日期 → 商户/备注
→ 预览余额/预算影响 → 保存 → 成功反馈 → 回到原页面并刷新
```

- 金额输入优先获得焦点；键盘不遮挡主按钮。
- 转账强制出现转出账户与转入账户，禁止用普通支出代替。
- 保存前显示账户余额、预算剩余和是否可能重复；保存后立即给出统一账单详情入口。
- 失败保留全部输入；离开未保存表单时显示系统确认 Sheet。

### 6.4 账户、分类与预算管理

- 使用分段入口：账户 / 分类 / 预算，避免把三类实体混在一张长表中。
- 账户行显示名称、类型、当前余额、最近更新时间和归档状态；点击进入余额变动。
- 分类行显示收支适用范围、预算关联数量和是否启用；分类名是稳定引用，不能只依赖自由文本。
- 预算行显示周期、已用、剩余、进度和超预算状态；编辑后显示生效周期和审计。
- 所有“新增”使用右上角单一主按钮；删除改为归档，避免破坏历史账单。

### 6.5 实物资产

- 列表显示资产名称、状态、累计净成本、最近事件和成本趋势入口。
- 详情显示购入、维护、耗材、升级、出售/转让/处置事件时间线；每个事件必须能进入关联账单或显示“无关联账单”的明确状态。
- 成本趋势图和事件列表使用相同过滤条件，切换购买/维护/回收时保留上下文。
- 新资产/新事件保存后进入详情，不回到无上下文的首页。

### 6.6 导入账单与关联审核

向导固定为：

```text
选择文件 → 识别预览 → 表头与数据起始行 → 字段映射
→ 标准化检查 → 关联候选审核 → 提交预览 → 提交结果
```

- `accept` 覆盖 PRD 允许的 CSV/XLS/XLSX/TXT/PDF/ZIP；不支持的格式在选择时说明原因。
- 表格预览固定左侧行号，表头行与数据起始行可点击；底部显示“已选第 X 行为表头、从第 Y 行开始读取”。
- 向导支持上一步、下一步、暂存批次、恢复批次；不可用“稍后继续”文案却没有历史入口。
- 每个候选显示 `confidence`、`reason_codes`、来源账单、银行锚点、是否重复、建议动作。
- 提交摘要的四类数字都是可点击入口；失败项可下载错误报告或回到对应行修正。
- 提交成功后显示批次、入账数、去重数、待审核数、失败数和原始文件保留到期日。

### 6.7 财务 AI

- 小兔子入口只读取当前家庭、当前周期、当前页面上下文；不跨家庭、不默认修改账。
- 结果卡必须展示摘要、来源账单、生成时间、Provider、model、适用周期和可信提示。
- AI 建议写入时先进入 `AIActionProposal`：预览 → 权限校验 → 确认 → 执行 → 审计；拒绝、撤销、过期都可见。
- AI 失败显示“重新生成”和“查看原始数据”；不把无法调用伪装成空数据。

### 6.8 权限与审计

- 先显示当前操作者，再显示家庭成员列表；所有者可编辑，其他成员根据授权显示只读/可写标签。
- 儿童行默认拒绝，开关旁显示权限具体范围，不只显示一个模糊“财务权限”。
- 保存时显示变更前后差异；成功后显示审计记录入口。
- 审计列表显示动作、操作者、目标、时间、结果、撤销关联；危险动作需要二次确认。

## 9. 全局状态与反馈组件矩阵

| 状态 | 视觉 | 文案结构 | 必须动作 |
|---|---|---|---|
| Loading | 保留原布局的骨架，避免整页跳动 | “正在加载 X” | 非必要不提供取消；允许系统返回 |
| Saving/Submitting | 主按钮 spinner + 文案变化 | “正在保存/提交” | 防重复提交，输入不丢失 |
| Success | 绿色语义 + 简短 toast/状态条 | “已保存/已导入 X 条” | 提供查看详情，自动刷新相关区块 |
| Error | 稳定内容表面 + 危险图标/文字 | 原因 + 是否影响数据 + 下一步 | 重试、查看详情或返回 |
| Forbidden | 不展示不可用数据 | “当前成员没有查看/编辑权限” | 返回或申请所有者授权 |
| Expired | 中性警告，不误报数据丢失 | “这条入口已过期，请重新获取” | 重新加载来源页面 |
| Conflict | 明确发生了并发/版本变化 | “数据已被更新，请选择保留哪一版” | 查看差异、重新加载、取消 |
| Empty | 内容容器仍保留层级 | 原因 + 价值说明 | 每个空态最多一个主要动作 |
| Offline/Network | 不清空已经展示的旧数据 | “暂时无法更新，显示的是上次数据” | 重试，必要时显示更新时间 |

1. 导入向导恢复、错误报告、候选原因码和结果下钻；
2. AI provider/model/time/source/权限/提案状态展示；
3. AdaptiveValue 长金额策略和受控兔子品牌资产；
4. 空趋势、空预算、导航安全区和长列表滚动优化；
5. 屏幕阅读器、大字号、减少透明度和 320pt 视觉回归。

### 阶段 C：统一美化收口

1. 以 Token、间距、圆角、字体、阴影和状态色做一次全财务页面清理；
2. 以 430pt 为主视觉金样，以 390pt 做常规适配，以 320pt 做安全边界；
3. 对首页、明细、详情、导入、预算、资产、权限、AI 逐页截图审查；
4. 只有业务闭环和视觉/交互矩阵同时通过，才标记为财务 UI/UX 收口。

## 12. Definition of Ready / Done

### 12.1 开始某个页面切片前（Ready）

- 页面目标、用户任务、入口和退出路径已经明确；
- 数据字段、权限、错误码和 `drilldown_ref` 已确定；
- 页面状态矩阵至少覆盖 loading/success/empty/error/forbidden/expired；
- 430/390/320pt 版式和键盘/系统返回策略已确定；
- 主动作不超过一个，次级动作有明确承载位置；
- 视觉稿、组件 Token 和交互说明相互一致。

### 12.2 页面切片完成（Done）

- 用户能从入口完成主任务，并能回到原上下文；
- 所有展示数据入口可下钻到对应账单/事件/来源；
- 所有非成功状态可触发明确下一步；
- 权限、审计、幂等和冲突状态有真实接口验证；
- 430/390/320pt 无元素溢出，无依赖隐藏溢出的假通过；
- 关键控件 44pt，Sheet 焦点和系统返回通过；
- 大字号、减少动态效果、长金额、长标题和多预算通过；
- typecheck、build、API/数据库测试和真实浏览器截图均留证；
- 文档、OpenAPI、运行时路由、前端类型和验收证据同步更新。

## 13. 最终审美验收清单

验收人必须用“连续阅读 10 秒”的方式看每个页面：

- 第一眼能否知道当前在哪个财务层级？
- 第一主动作是否明确，是否被工具按钮抢走注意力？
- 金额是否比装饰更突出，正负与周期是否清楚？
- 圆环和趋势是否既美观又告诉用户下一步可以点哪里？
- 淡粉淡紫是否只提供温度，没有降低可读性？
- 卡片、按钮、文字是否遵循同一套间距与排版，而不是每个页面各自“调好看”？
- 发生失败、无权限、过期或冲突时，用户是否立即知道原因和可执行的下一步？
- 关闭 Sheet、返回详情、重试数据、恢复导入时，交互是否符合 iOS 直觉？
- 430pt 看起来是否有呼吸感，320pt 是否仍然不挤、不溢出、不丢信息？

**收口标准：**不是“截图看起来漂亮”即通过，而是“视觉层级漂亮 + 交互路径可预测 + 每个数字可查证 + 每种状态可恢复 + 每个权限边界可解释”。
