# Life UI 重设计方向与实施契约 v0.1

状态：高保真概念稿评审版，尚未写入现有页面代码

生成稿：[Life-UI 重设计概念稿](./Life-UI重设计概念稿-v0.1.png)

## 1. 这次重设计要解决的问题

当前界面已经具备统一的淡粉、淡紫和兔子品牌识别，但存在三个需要收口的问题：

1. 内容层、功能层和玻璃层的边界不够稳定，容易出现“所有东西都像玻璃”的视觉噪音。
2. 财务信息很多，预算环、金额、趋势图和操作入口之间的主次关系还可以更清楚。
3. 页面虽然有按钮和卡片，但部分图标、文字和容器的语义不够系统，后续页面扩展容易产生局部风格漂移。

本版方向：保留 Life 的温柔家庭氛围和白兔形象，但将视觉重心从“装饰性玻璃”转向“内容优先、交互清晰、层级稳定”。

## 2. 总体设计原则

### 2.1 三层结构

- 环境层：淡紫到淡粉的低饱和渐变，只负责氛围，不承载核心文字。
- 内容层：近白色的实体表面，承载家庭动态、账单、预算和图表，保证阅读稳定。
- 功能层：Liquid Glass 只用于底部导航、小兔子入口、浮动控件和 Bottom Sheet。

Apple 当前的 Liquid Glass 指南也强调，它适合导航和控件等功能层，不应大面积用于内容层；因此本版会把玻璃效果从内容卡片中撤出。[Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

### 2.2 一屏一个主动作

- 家庭空间：首页主动作是“发布想法”。
- 财务首页：首页主动作是“＋ 新增记账”。
- 导入账单：当前步骤主动作是“上传并登记导入批次”。
- 其它动作降级为次按钮、文字按钮或整行点击入口。

### 2.3 信息先于装饰

兔子是品牌和 AI 的识别入口，不重复出现在每一张卡片中；装饰光晕、渐变和插画不覆盖金额、标题、趋势和状态。

## 3. 视觉 Token

### 3.1 颜色

| 角色 | 建议值 | 用途 |
|---|---|---|
| 页面底色 | `#F7F4FC` | 全局背景 |
| 内容表面 | `#FFFEFF` | 内容卡片、列表、图表容器 |
| 内容边界 | `#E8E6F3` | 轻描边和分隔线 |
| 主文字 | `#20223E` | 标题、金额、核心事实 |
| 次文字 | `#6E718C` | 描述、时间、来源 |
| 主操作 | `#6259E8` | 主按钮、选中态、主链接 |
| 主操作按下 | `#4C46C7` | pressed 状态 |
| 家庭空间 | `#6678E8` | 家庭空间图标和选中态 |
| 吃什么 | `#E6A13D` | 食物推荐和菜谱入口 |
| 财务 | `#35A47A` | 财务模块身份色 |
| AI | `#9A79E8` | 小兔子 AI 和 AI 提案 |
| 支出/危险 | `#D6536D` | 支出、超预算、错误 |
| 收入/成功 | `#2D9B72` | 收入、成功、已完成 |

颜色只表达语义，不用相近的紫粉色随意新增模块色。内容层必须优先保证对比度，不能依赖透明度让文字可读。

### 3.2 尺寸和圆角

- 页面左右边距：16pt。
- 内容区块间距：20–24pt。
- 卡片内边距：16pt。
- 主要触控区域：至少 44×44pt。
- 普通内容卡片：20pt 圆角。
- 重要 Hero 卡片：24pt 圆角。
- 输入框和按钮：14–16pt 圆角。
- Bottom Sheet 顶部圆角：28pt。
- 底部导航：24pt 圆角，保留安全区间距。

### 3.3 文字

- 页面标题：28/34，最多两行。
- 区块标题：20/26。
- 卡片标题：16–18/22。
- 正文：15/22。
- 辅助信息：12–14/18。
- 金额使用等宽数字、右对齐；过长时优先增高容器，再使用短格式，不覆盖其它内容。
- 长标题和按钮文案使用平衡换行，不用固定高度强行截断核心信息。

## 4. 图标系统

- 使用 SF Symbols 风格的线性图标，统一 1.75–2pt 描边。
- 图标尺寸：导航 20pt、卡片 22pt、空态/重点入口 28pt。
- 图标不能再使用随意的 Unicode 符号代替正式图标。
- 图标只表达“是什么”或“可以做什么”，状态必须同时有文字。
- 一级导航固定为：家庭空间、吃什么、财务、更多；HowToCook 继续作为吃什么的子页面，不进入一级导航。
- 小兔子只作为 AI 入口、AI 生成中和 AI 提案状态的品牌标记。

## 5. 三个核心页面的版式契约

### 5.1 家庭空间首页

上方是紧凑品牌头部：Life、家庭生活工作台和小兔子 AI 入口；下面只保留一个 Hero 卡片，表达“把想法放在一起，一起把生活过好”。

Hero 卡片包含：

- 一句主标题。
- 一段解释文字。
- 一个“发布想法”主按钮。
- 低干扰的兔子插画，不能抢过文字。

Hero 下方使用“最近动态”列表：整行可点击、左侧为语义图标、右侧为时间和 chevron。底部使用固定四项导航，选中态以轻量胶囊背景表达，不使用大面积高斯模糊。

### 5.2 财务首页

页面顺序固定为：上下文标题 → 周期切换 → 新增记账 → 核心摘要 → 本月预算 → 收入支出趋势 → 最近流水。

#### 预算多环

- 所有预算分类放在一个圆形视觉单元中。
- 每个预算分类使用一个同心环；每个环有自己的颜色和进度。
- 环下方或右侧配自适应图例，显示分类名、已用金额、余额和比例。
- 分类数量增加时，图例使用自适应网格自动换行，不缩小到不可读；超过 6 项时默认显示前 5 项和“其他”。
- 点击某一环或图例时，该环高亮，其余环降低对比度，并进入对应预算分类流水。
- 环中心显示当前总已用金额和剩余金额，不能只显示百分比。
- 超预算时使用危险色、缺口文字和纹理/线型辅助，不能只靠把环变红。

#### 收入支出趋势

- 收入和支出使用两条有明确图例的线。
- 数据点可以点击，点击后弹出日期/周期摘要。
- “查看明细”作为清晰的二级入口，进入对应筛选后的流水。
- 图表容器固定高度，加载时保留骨架尺寸，避免页面跳动。

### 5.3 导入账单 Sheet

- Sheet 负责短流程，不把导入流程做成全屏复杂页面。
- 顶部显示当前步骤和总步骤，用户随时知道位置。
- 来源选择使用可点击的来源卡：银行、支付宝、微信支付、记账 App、其他。
- 文件区域必须同时说明支持格式、单文件限制和原始文件保留策略。
- 主按钮明确当前阶段动作，未选择文件时禁用但保持可理解的禁用原因。
- 关闭、下滑关闭和暂存恢复都保留，避免用户丢失已完成的步骤。

## 6. 交互与反馈契约

- 点击卡片：按下态即时变化，整行命中区域不小于 44pt。
- Bottom Sheet：支持抓手下滑、关闭按钮和系统返回；键盘出现时主按钮不能被遮挡。
- 图表、圆环、金额卡和账单行都是可交互入口，必须提供按下态、选中态和加载态。
- 写入动作：按钮进入进行中状态，成功后给出轻量确认；错误时保留输入并提供重试。
- AI 动作：只生成待确认提案，显示来源、生成时间和写入范围，确认后才执行。
- 降低透明度时，玻璃组件退化为不透明浅色表面，布局和语义不改变。

## 7. 后续代码实施顺序

确认本设计方向后，按以下顺序修改，不先局部调色：

1. 建立全局颜色、间距、圆角、阴影、字体和交互状态 Token。
2. 统一 App Shell、底部导航、按钮、图标按钮、内容卡片和 Bottom Sheet。
3. 先改家庭空间首页，验收导航、Hero、动态列表和 AI 入口。
4. 再改财务首页，重点验收多环预算、趋势图和点击下钻。
5. 最后统一财务工具、账户预算、资产、导入、记账、流水和 AI Sheet。
6. 在 320pt、390pt、430pt 和大字号条件下复核换行、自动排版和安全区。

本契约只在用户确认高保真视觉方向后进入代码修改阶段；当前不会覆盖现有实现。
