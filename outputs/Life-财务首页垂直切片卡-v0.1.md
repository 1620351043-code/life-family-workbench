# Life 财务首页垂直切片卡 v0.1

更新时间：2026-08-25
状态：实现完成，待真实运行态验收

## 1. 页面定义

- 页面名称：财务首页
- 一级入口：底部导航「财务」
- 页面核心任务：让家庭成员在一个移动端页面看懂当前周期的收入、支出、预算执行和实物资产成本，并能从任意数据展示直接进入对应明细。
- 页面不负责：导入文件、表头识别、字段映射、关联审核、预算编辑、资产编辑。这些作为后续独立垂直切片进入。
- 数据边界：只读取当前会话对应的 `household_id`，不在客户端拼接家庭范围。
- 数据来源：PostgreSQL `FinanceOverview` 和服务端生成的 `drilldown_ref`，禁止使用默认财务 fixture 冒充成功数据。

## 2. 页面内容与交互

### 2.1 页面结构

1. 财务标题、周期选择和小兔子上下文入口；
2. 收入、支出、净现金流摘要卡；
3. 多预算同心圆环：中心显示整体预算，外环显示分类进度；
4. 预算分类图例：自动 1/2/3 列布局，超过 6 类显示「其他」汇总；
5. 收入/支出/净现金流趋势图；
6. 实物资产成本趋势图：采购、维护、回收和净现金成本；
7. 点击后的明细底部表单/列表；
8. 点击统一账单后的交易详情页/详情层，并展示来源记录和关联关系。

### 2.2 交互契约

| 触发对象 | 反馈 | 数据入口 |
|---|---|---|
| 收入/支出/净现金流卡片 | 打开对应账单明细 | 卡片 `drilldown_ref` |
| 预算中心 | 打开当前周期预算关联账单 | `budget_center.drilldown_ref` |
| 单个预算环 | 打开该分类账单 | `budget_rings[].drilldown_ref` |
| 趋势线/趋势点 | 打开对应周期账单 | `trend_points[].drilldown_ref` |
| 资产成本线/数据点 | 打开对应资产事件 | `asset_cost_points[].drilldown_ref` |
| 明细列表项 | 打开统一账单详情 | `/api/finance/transactions/{transactionId}` |
| 来源记录 | 展示银行/支付宝/微信/记账 App 原始关系 | `TransactionDetail.source_records` |

所有图表和圆环都是可交互数据入口，不允许只做装饰性绘图。

## 3. 必须覆盖的页面状态

- 加载中：保留卡片和图表尺寸，避免跳动；
- 正常数据：展示真实数据和来源可下钻入口；
- 无预算：圆环显示空状态，并引导创建预算；
- 无趋势数据：保留坐标容器，说明当前周期暂无账单/资产事件；
- 空明细：说明筛选条件，不展示伪造数据；
- 网络错误：显示原因和重试，不清空用户当前周期选择；
- 下钻过期：提示重新获取首页数据；
- 无财务权限：说明当前成员无权查看，不泄露其它家庭信息；
- 长分类名/长金额/大字号：使用总体 UI 设计系统的自适应容器和 `AdaptiveValue`；
- 320–430pt：预算分类分别覆盖 1、3、5、6、超过 6 项；
- 降低透明度/减少动态效果：玻璃退化为稳定浅色层，交互语义不变。

## 4. API 与数据库验收

- `GET /api/finance/overview` 返回完整 `FinanceOverview`；
- 所有摘要卡、预算环、趋势点和资产点都必须携带服务端生成的 `drilldown_ref`；
- `GET /api/finance/drilldowns/{filterId}` 必须按当前家庭执行服务端过滤；
- `GET /api/finance/transactions/{transactionId}` 必须返回统一账单、来源记录和关联关系；
- 越权家庭的过滤器、账单和来源记录返回 404/403，不得泄露存在性；
- OpenAPI、运行时路由、仓储接口和测试同步更新；
- 页面成功态必须来自 PostgreSQL 查询，不接受 fixture 默认回退。
