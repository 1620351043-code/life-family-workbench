## 3. 本轮已落地的共享层收口

本轮只修改不改变业务数据语义的公共层：

- 一级导航按钮补充 `type="button"`、`aria-current="page"`，图标标记为装饰性内容，避免读屏重复播报。
- 加载状态补充 `role="status"` 与 `aria-live`，错误反馈保留可关闭的即时反馈。
- 小兔子入口、返回、AI 关闭、评论和主题卡片统一按钮语义。
- Sheet 关闭按钮、分段选择、财务周期切换和已有主次按钮统一到 44pt 触控目标。
- 增加顶部安全区变量，避免刘海/灵动岛设备上内容贴边；滚动容器增加纵向 overscroll 约束。
- 页面根节点禁止横向溢出；动态标题、金额和列表继续使用现有自适应容器与换行规则。
- 保留减少透明度与减少动态效果降级路径，不改变功能层级。

本轮明确没有做的事情：

- 没有修改财务账单去重、关联审核、真实写入和 PostgreSQL 确定性查询。
- 没有接入腾讯云 COS。
- 没有实现吃什么业务，只收口公共 UI 基础，避免在占位页面上堆临时逻辑。

## 4. 全局 UI/UX 验收标准

### 4.1 视口与布局

- 设计基准：`430×932`；最小验收宽度：`320×900`。
- `document.documentElement.scrollWidth <= viewport.width`，禁止横向滚动条。
- 内容主轴只有纵向滚动；预算图例、筛选项和卡片组使用自适应换列，不把横向滚动藏进小卡片。
- 底部导航、Bottom Sheet 和输入区均避让 `safe-area-inset`。

### 4.2 触控与反馈

- 可交互元素的命中区域默认不小于 `44×44pt`；视觉图标小于 44pt 时用 padding 扩大命中区。
- 点击、提交、确认、拒绝、错误、加载和空态必须有即时可理解反馈。
- 图表、预算环和整行账单/主题卡片均必须能进入对应下钻或详情。
- 不使用颜色作为唯一状态信号；至少同时提供文字、图标、数值或线型差异。

### 4.3 视觉一致性

- 页面只使用 `outputs/Life-移动端总体UI设计系统-v0.1.md` 中定义的颜色角色、间距、圆角和层级。
- 淡粉和淡紫只用于环境氛围；内容表面负责可读性；Liquid Glass 只用于导航、Sheet 和浮动控件。
- 预算新增分类时自动换列和增高；1、3、5、6、超过 6 项均不得重叠、溢出或压缩到不可读。
- 长标题、长金额、中英文混排和大字号场景优先换行/增高，其次才在安全范围内缩小字号。

## 5. 下一张垂直切片：吃什么 → HowToCook

### 5.1 页面范围

1. 吃什么首页：今日推荐、智能搭配入口、搜索入口、最近吃过和长期习惯推荐展示。
2. 智能搭配：人数、分量、今天想吃/不想吃等最少必要输入。
3. 推荐结果：主菜单、备选菜单、推荐理由和选择确认。
4. HowToCook 菜谱详情：食材、工具、步骤、份数调整和收藏。
5. 采购清单：由已确认菜谱生成，可勾选并回溯来源菜谱。
6. 自动历史：系统根据确认、打开、烹饪和采购行为采集，只提供展示页，不增加重复手动录入。

### 5.2 业务边界

- HowToCook 继续作为“吃什么”的子页面，不新增一级导航。
- 菜谱内容来自最新版 HowToCook 的本地解析结果，建立 `raw → parsed → normalized` 单一流水线。
- AI 负责解释和推荐，不替用户自动确认菜谱、生成采购清单或写入家庭偏好。
- 推荐服务不可用时降级到可解释的规则推荐，吃什么首页不能空白。

### 5.3 下一张切片的 Definition of Done

- 页面立项、状态图、交互规则和 API/数据契约先写入切片卡。
- 菜谱数据能从本地解析产物稳定读取，不使用硬编码演示菜谱作为默认成功路径。
- 从推荐 → 用户确认 → HowToCook → 采购清单真实打通。
- 移动端在 `430×932` 和 `320×900` 完成正常、空态、加载、错误、长菜名和多食材验收。
- 自动历史和长期习惯只由行为事件产生，并能展示来源时间和家庭范围。
- 前端类型检查、生产构建、API 测试和浏览器端点击验收通过后，才进入下一张切片。

## 6. 下一阶段不进入当前主线的事项

- “更多”页面：等待家庭饮食与财务核心闭环稳定后再设计，不提前扩展设置类入口。
